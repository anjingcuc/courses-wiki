## 逐字稿

### [0:00–0:30] 开场 Hook

**【画面】** 黑屏，逐字打出大字：`AI 都能写代码了，你还学编程干嘛？` 随后画面切到 Kimi Code / Trae 界面中 AI 生成代码的快进画面。

**【旁白】**
这句话，大概是很多同学心里最大的疑问。ChatGPT 写代码，Cursor 写代码，连手机上的大模型都能写代码了——那这门 Python 课，到底还有没有必要上？今天我先用 8 分钟，把这个问题给你彻底聊明白。

---

### [0:30–1:30] 成果前置：10 分钟做出 AI 聊天网页

**【画面】** 浏览器中打开一个 AI 聊天网页，输入"你好"，大模型回复文字。画面左下角字幕条：`这个网页用 AI 辅助，从零到跑起来不到 10 分钟`。

**【旁白】**
先给你看个东西。这是一个 AI 聊天网页，能跟大模型对话，界面还挺像样。整个东西，用 AI 辅助，从零到能跑，不到 10 分钟。这就是你们学期末期末项目的雏形——一个完整的 AI 应用。听起来很酷对吧？但重点来了：这个网页的代码全是 AI 生成的，可如果没有任何编程基础，你连它跑不跑得起来都不知道，更别说改了。所以问题就变成了：AI 时代，人到底该学什么？

---

### [1:30–3:30] 核心知识点：三种不可替代的能力

**【画面】** 字幕条依次弹出三个关键词，配图标：`① 读代码` `② 调试` `③ 系统设计`。

**【旁白】**
答案是三件事。第一，读代码。AI 写出来的代码，你得看得懂，才能判断它写得对不对、安不安全。比如刚才那个网页，AI 把 API 密钥直接写在了代码里——这是一个安全隐患，后面课程会专门讲怎么处理。但如果你不懂代码，这个风险你根本看不见。

第二，调试。AI 不会一次性写对。报错了、行为不对了，你得能定位问题出在哪、知道怎么修。这是纯靠 AI 给不了你的能力。

第三，系统设计。AI 是执行者，但做什么、做成什么样、分几个模块——这些大方向是人来定的。打个比方：AI 是自动驾驶的辅助系统，你是机长。平时它帮你干粗活，但关键时刻，你得能接管方向盘。

---

### [3:30–6:00] vibe coding 工作流拆解

**【画面】** 录屏回放刚才网页的生成过程（快进），在关键节点暂停并打上字幕标注：`第1步：描述需求` → `第2步：AI生成代码` → `第3步：人审查` → `第4步：运行验证` → `第5步：微调迭代`。

**【旁白】**
我们把刚才那个网页的制作过程拆开来看。第一步，描述需求。我告诉 AI：我要一个聊天界面，前端用 HTML 和 JavaScript，后端用 Python 的 FastAPI 调用大模型 API。注意，这个描述本身就是一种能力——你描述得越精准，AI 给的结果越好。第二步，AI 生成代码，这个它来干。第三步，人审查。我快速扫了一遍生成的代码，结构对不对、逻辑通不通、有没有明显的问题。第四步，运行验证。把后端跑起来，浏览器打开前端，输入消息，看 AI 能不能正常回复——如果报错了，就得调试。第五步，微调。比如我对 AI 说"把背景改成深色主题"，它就帮我改好了。

整个流程里，AI 干了最耗时的"写代码"环节。但需求怎么描述、结果对不对、出了问题怎么修——每一步的决策权都在人手里。这就是 vibe coding：你用自然语言指挥 AI，但你不放手不管。

---

### [6:00–7:30] 考核方式与学习路线

**【画面】** 字幕条/卡片展示成绩结构：`平时作业 50%（5次）+ 期末大项目 50%（含答辩）`，底部红字标注 `无上机考试`。

**【旁白】**
再说说这门课怎么打分。没有上机考试。成绩一半来自平时作业，一共 5 次编程任务，允许你用 AI 辅助，但要求你能说清楚思路。另一半是期末大项目——你或者你们小组，从零做一个完整的 AI 应用，然后答辩。注意"答辩"两个字：到时候老师会随机指着你项目里的一行代码问，"这是干什么的"。如果全靠 AI 写、你一行都解释不了，那答辩是过不了的。所以从第一天起，态度就很明确：AI 是副驾驶，你是机长。

---

### [7:30–8:25] 小结、提问彩蛋与下集预告

**【画面】** 三个关键词再次出现：`读代码 · 调试 · 系统设计`。

**【旁白】**
总结一下：AI 时代学编程，不是学怎么从头背每一条语法，而是学怎么读代码、调代码、用 AI 高效地把东西做出来。这门课 48 节，带你从零到做出一个属于自己的 AI 应用。

**【画面】** 字幕条逐条弹出三个可直接照抄的 prompt（每条停留供暂停截图）：
① `我是 Python 零基础学生。请围绕"读代码、调试、系统设计"这三种能力各出一道思考题，我回答之后你再逐条点评。`
② `给我一段 20 行左右的 Python 代码，故意埋下 2 个 bug，先别告诉我答案，让我练习读代码找问题。`
③ `用生活里的类比解释"AI 是副驾驶、人是机长"，再举一个完全放手让 AI 写代码导致翻车的例子。`

**【旁白】**
最后留个提问彩蛋。下次打开 Kimi 或 DeepSeek，别急着让它替你干活——让它当你的老师：给你出题、让你找茬、讲清楚为什么。这三句直接照抄去用。记住，AI 不光能帮你写代码，更能帮你学会代码，差别全在怎么问。

**【画面】** 弹出下集标题卡：`V002 用大模型学编程的正确姿势`。

**【旁白】**
下一集我们讲一个比语法更重要的东西：怎么向 AI 提问，才能得到高质量的代码。我们下集见。

## 演示操作清单

> 本课演示为"终局预览"，目的是建立目标感，不要求学生理解每行代码。课前需预跑一遍，保存成功版本作为备份。

### 课前环境确认

```bash
kimi-code --version       # 确认 Kimi Code 已安装
python --version          # 确认 Python 3.10+ 可用
ping api.deepseek.com     # 确认网络通畅
```

### vibe coding 演示 Prompt

对 Kimi Code 的完整 prompt：

```
帮我创建一个 AI 聊天网页，包含两个文件：

1. app.py：FastAPI 后端
   - POST /chat 接口，接收 {"message": "用户消息"}
   - 调用 DeepSeek API（openai SDK 兼容模式）
   - 返回 {"reply": "AI回复"}

2. index.html：前端聊天界面
   - 消息列表区域 + 输入框 + 发送按钮
   - 用 fetch 调用 /chat 接口
   - 简洁美观的 CSS 样式

API Key 用环境变量 DEEPSEEK_API_KEY 读取，不要硬编码。
```

### 运行验证命令

```bash
pip install fastapi uvicorn openai python-dotenv
uvicorn app:app --reload --port 8000
# 另开终端，浏览器打开 index.html
```

### 微调 Prompt（演示迭代修改）

```
把 index.html 的背景改成深色主题，聊天消息用气泡样式，
用户消息靠右、AI消息靠左。
```

## 录制注意

1. **预跑备份**：vibe coding 演示依赖网络和 AI 服务，课前务必预跑一遍并将成功的 `app.py` + `index.html` 存到本地。如果录制时网络出问题或 AI 生成有 bug，直接切换到预存版本展示成品效果。
2. **审查环节要真实**：第三步"人审查"时，故意指出"API Key 写在代码里"这个问题——这是真实的代码审查场景，不要跳过。
3. **字幕条重点**：三种能力（读代码/调试/系统设计）和工作流五步（描述→生成→审查→运行→微调）必须配字幕条，这是学生要记住的核心概念。
4. **时长控制**：vibe coding 拆解段（3:30–6:00）是弹性段，如果录屏回放太长可以快进压缩；开场 hook + 成果前置合计不超过 1 分 30 秒。
5. **提问彩蛋**：提问彩蛋段的 prompt 字幕条需在后期加上，确保观众能暂停照抄。
