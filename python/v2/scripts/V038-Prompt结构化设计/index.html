    逐字稿¶

    [0:00-0:30] 开场 hook（成果前置：同一段代码，两种 prompt，天差地别）¶

    【画面】 屏幕分屏对比——左侧是一段模糊 prompt 的输出（一大段笼统的文字，"这段代码可以实现功能，但有一些可以改进的地方……"），右侧是结构化 prompt 的输出（清晰的四维评分表 + 问题清单 + 改进代码）。中间打字幕条："同一个问题，两种问法，结果天差地别"。

    【旁白】 同一段代码，同一个 AI 模型——左边问"帮我分析这段代码"，AI 回复了一大段话，看完还是不知道该改什么；右边换了个问法，AI 直接给了四维评分、问题清单和修复后的代码。区别在哪？不在 AI，在 Prompt。今天我们学一个框架——五组件结构，让你的 prompt 从"发消息"变成"发指令"。

    [0:30-1:15] 核心认知：Prompt 不是聊天，是编程¶

    【画面】 PPT 动画——左边是微信聊天气泡（随意、口语化），右边是代码编辑器（结构化、有约束）。箭头从左边指向右边，字幕："Prompt 不是聊天 → Prompt 是编程"。

    【旁白】 先建立一个核心认知——Prompt 不是聊天，Prompt 是编程。

    你在微信里跟朋友说"帮我写个函数"，朋友会追问你一堆细节——写什么函数？什么参数？什么格式？但大模型不会追问——它按自己的理解直接生成，结果就是你得到一个"万能但没用"的函数。

    你写的每一段 prompt，都在**编程 AI 的行为**——限定它的角色、规定它的任务、约束它的输出。越精准，输出越可控。

    怎么做？靠五组件结构。

    [1:15-4:45] 五组件逐个讲解（逐步叠加）¶

    【画面】 屏幕中央显示一个初始 prompt 文本框。每讲一个组件，往上面叠加一层（用不同颜色高亮新加入的部分），旁边小字标注"组件 X / 5"。右边实时滚动展示 AI 输出的变化。

    【旁白】 结构化 prompt 有五个组件。我们一个一个叠加上去看效果。

    组件一——角色定义。 就是一句话："你是谁"。

    prompt = "你是一个资深 Python 工程师。"

    这一句看似简单，但它设定了 AI 回复的专业程度和视角。说"你是 Python 工程师"，它就不会用外行语言给你解释。

    组件二——任务描述。 "你要做什么"。

    prompt = """你是一个资深 Python 工程师。

请审查以下代码的质量。"""

    光说"写个函数"不够——得说具体做什么。这里任务很明确：审查代码质量。

    组件三——约束条件。 "必须怎样，不要怎样"。

    prompt = """你是一个资深 Python 工程师。

请审查以下代码，从四个维度评分：
1. 健壮性
2. 可读性
3. 安全性
4. 性能

不要泛泛而谈，每条问题必须给出具体代码位置。"""

    约束条件的核心是**收窄输出空间**——"不要泛泛而谈"把 AI 从"写一大段废话"逼到"逐条找问题"。

    组件四——输出格式。 "按什么格式给我"。

    prompt = """你是一个资深 Python 工程师。

请审查以下代码，从四个维度评分：
1. 健壮性
2. 可读性
3. 安全性
4. 性能

请按以下格式输出：
## 评分
- 健壮性：X/5
- 可读性：X/5
（...）

## 问题清单
（逐条列出）

## 改进建议
（给出改进后的代码）"""

    你规定了格式，AI 就不会天马行空地组织内容——它会严格按"评分、问题、建议"三段式输出。这一步对后续程序解析 AI 的回复特别重要。

    组件五——示例。 "好结果长这样"。这个组件威力最大，我们下集单独讲。今天先把骨架搭好。

    这五个组件不需要每次全用——但**至少要有角色、任务、输出格式三个**。组件越全，输出越精准。记住这个渐进过程：加一层组件，输出质量提升一档。

    [4:45-6:15] 可运行闭环：v1→v2 prompt 迭代¶

    【画面】 VS Code 中打开两个文件——demo_v1.py 和 demo_v2.py。先运行 v1，终端输出一大段笼统评价；再运行 v2，终端输出结构化评分表。两次输出并排对比。

    【旁白】 现在用一个可运行的例子把五组件用起来。场景——让 AI 审查一段代码。

    先看 v1，最朴素的提问：

    from llm_utils import llm_chat

code_to_analyze = '''
def get_data(url):
    d = requests.get(url).json()
    return d["results"]
'''

prompt_v1 = f"帮我分析这段代码的质量：\n{code_to_analyze}"
print("=== V1: 模糊提问 ===")
print(llm_chat(prompt_v1))

    运行一下——输出是一大段文字，"这段代码可以工作但存在一些问题……"。泛泛而谈，没有评分，没有结构。

    现在换 v2——把角色、任务细化、格式约束全加上：

    prompt_v2 = f"""你是一个资深 Python 代码审查专家。

请审查以下代码，从四个维度评分（1-5分）并给出改进建议：
1. 健壮性（异常处理、边界情况）
2. 可读性（命名、注释、结构）
3. 安全性（敏感信息、注入风险）
4. 性能（效率、资源管理）

代码：
{code_to_analyze}

请按以下格式输出：
## 评分
- 健壮性：X/5
- 可读性：X/5
- 安全性：X/5
- 性能：X/5

## 问题清单
（逐条列出发现的问题）

## 改进建议
（给出改进后的代码）"""

print("=== V2: 结构化提问 ===")
print(llm_chat(prompt_v2, temperature=0.3))

    运行——AI 严格按四维评分输出，给了具体分数、逐条问题、修复后的代码。同一段代码、同一个模型，问法不同，输出天差地别。这就是结构化的威力。

    注意两个细节——一是用 f-string 把 code_to_analyze 作为变量注入，固定部分写死、变化部分用变量填，这跟 L6 学的字符串格式化完全一样。二是 temperature 设成 0.3——代码审查需要准确性，不需要创意。

    [6:15-7:15] Prompt 急诊：诊断一段烂 prompt¶

    【画面】 屏幕上出现一段 prompt，标注红色"⚠ 病人：帮我写一个数据处理函数"。旁边逐条标注诊断结果——缺任务描述✗、缺约束条件✗、缺输出格式✗、缺示例✗。

    【旁白】 来做一个实战练习——Prompt 急诊。

    看这段 prompt："帮我写一个数据处理函数"。跑一下，AI 会给你一个"万能数据处理函数"——处理什么数据不知道、什么格式不知道、什么逻辑不知道。这个 prompt 病在哪？用五组件框架诊断：

    缺**任务描述**——处理什么数据？做什么操作？没说。 缺**约束条件**——输入输出格式？异常处理？没说。 缺**输出格式**——要不要 type hints？要不要 docstring？没说。 缺**示例**——没有告诉 AI"好结果长什么样"。

    五个组件缺了四个。怎么治？全补上——告诉它处理字典列表，清洗规则逐条列出来，给一组输入输出示例，规定用 type hints 写。改完后，AI 一次就能给你一个能直接用的函数。

    Prompt 工程不是玄学——烂 prompt 一定缺了某个组件。你的工作是诊断缺了什么，补上去。

    [7:15-7:45] Prompt 调试方法论¶

    【画面】 PPT 展示三条方法论，逐条弹出。旁边是一个 A/B 对比测试脚本的截图——for 循环跑 3 次，print 两个版本的输出。

    【旁白】 最后讲一个调试方法论——调 prompt 不靠"感觉"，靠数据。

    三条原则：第一，变量化——prompt 中的变化部分用 f-string 变量注入，固定部分写死。不要每次手写完整 prompt。第二，A/B 对比——改了一个组件，用同一个输入跑两个版本，对比输出。改了有效才保留。第三，边界测试——用空输入、超长输入测 prompt 的鲁棒性。

    这三条让你从"凭感觉改 prompt"变成"有方法论地迭代 prompt"。

    [7:45-8:00] 小结¶

    【画面】 字幕条："五组件：角色 · 任务 · 约束 · 示例 · 输出格式"。

    【旁白】 总结——五组件框架：角色定义、任务描述、约束条件、示例、输出格式。核心心法：Prompt 不是聊天，是编程。

    [8:00-8:20] 提问彩蛋¶

    【画面】 黑底字幕条逐条弹出三个 prompt（右上角标注"暂停照抄"）： 1. 「我在学 prompt 五组件结构（角色、任务、约束、输出格式、示例）。请你扮演面试官，围绕这五个组件轮流向我提问，每次只问一个，我回答后你点评并追问。」 2. 「给我出 3 道"烂 prompt 诊断"练习：每题给一段有缺陷的 prompt，让我用五组件框架指出缺了哪些组件，我答完再公布答案并讲解。」 3. 「用生活类比讲清楚"约束条件"和"输出格式"的区别，再举一个两者容易混淆的例子。」

    【旁白】 彩蛋时间——三个 prompt 直接抄走，去问 Kimi 或 DeepSeek。五组件看懂了不算会，被 AI 追问一轮才知道哪里虚。原则就一条：别把 AI 当答案机——让它给你出题、挑你的毛病，比你自己刷十遍笔记管用。

    [8:20-8:35] 引出下集¶

    【画面】 切换预告条："下集 → V039 Few-shot 与思维链技巧"。

    【旁白】 五组件给你骨架，但还有一种技巧能让输出质量再上一个台阶——给 AI 看几个例子，或者教它一步一步想。下集学 Few-shot 和思维链。

3. 安全性（敏感信息、注入风险）

代码：
{code_to_analyze}

请按以下格式输出：
## 评分
- 健壮性：X/5
- 可读性：X/5
- 安全性：X/5
- 性能：X/5

## 问题清单
（逐条列出发现的问题）

## 改进建议

    文件 3：prompt_ab_test.py¶

    # prompt_ab_test.py —— A/B 对比测试
from llm_utils import llm_chat

test_input = "这个产品太垃圾了，千万别买"

prompt_v1 = f"判断情感：{test_input}"
prompt_v2 = f"""你是情感分析专家。判断以下文本的情感，只输出"正面"、"负面"或"中性"。

文本：{test_input}
情感："""

print("=== V1（无结构）===")
for _ in range(3):
    print(llm_chat(prompt_v1, temperature=0))

print("\n=== V2（结构化）===")
for _ in range(3):
    print(llm_chat(prompt_v2, temperature=0))

    录制注意¶

    1. v1 和 v2 的输出对比是核心视觉冲击：录制前先各跑一次并截图保存。如果现场 API 调用失败，直接展示截图——对比效果不能丢。重点让观众看到"同一段代码、两种问法"的输出差异。
    2. 五组件叠加要有动画节奏：用 PPT 或编辑器的逐步高亮，每讲一个组件就往 prompt 上"加一层"。不要一次性展示完整 prompt——渐进叠加是这节课的核心叙事手段。示例组件在屏幕上展示但不展开讲，留到 V039。
    3. f-string 变量化要强调：录制时用光标指到 {code_to_analyze}，强调"这就是变量注入，和 L6 学的 f-string 一样"。这是把 prompt 从"手写死字符串"变成"可复用模板"的关键。
    4. "Prompt 急诊"段落要快：控制在 1 分钟内。核心是展示"拿着五组件框架去诊断，一定能找到问题"这个心法，不要在这里写完整改造代码。
    5. 提问彩蛋段的 prompt 字幕条需在后期加上，确保观众能暂停照抄。
