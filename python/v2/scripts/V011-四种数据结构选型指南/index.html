    逐字稿¶

    [0:00-0:35] 开场 hook¶

    【画面】 屏幕左边放一段 AI 返回的消息列表数据（JSON），右边放一个空 Python 文件，光标闪烁。字幕条："你的数据该用哪种结构存？"

    【旁白】 这是一段大模型 API 返回的对话记录——你看，它是一条消息套一条消息，每条消息又有 role 和 content 两个字段。现在我问你：用 Python 存这堆数据，你用列表、字典、元组、还是集合？

    选错了，代码多写三倍；选对了，一行搞定。今天我用四个一句话比喻，帮你彻底搞清楚这四种数据结构各自适合什么场景。学完之后，你看到任何数据都能秒判断该用什么存。

    [0:35-2:00] 四种结构一句话定位¶

    【画面】 PPT 动画：四个图标依次出现——排队的人（列表）、通讯录（字典）、塑封文件（元组）、筛子（集合）。每个图标下方一句中文定义。

    【旁白】 Python 有四种核心数据结构，每种我用一句话概括：

    列表——有序、可变，像排队。先来的排前面，可以随时加人也可以踢人。用方括号，按下标取值，[0] 是第一个。

    字典——键值映射，像通讯录。你不会说"通讯录第 0 个人是谁"，你会说"张三的电话是多少"——按 key 查 value。用花括号，data["name"] 直接取值。

    元组——不可变的列表，像塑封文件。一旦创建就不能改。用圆括号。什么时候用？当你想保证数据不被意外修改的时候。

    集合——唯一、无序，像筛子。倒进去一堆东西，重复的自动消失。最大特长：判断"某个东西在不在里面"特别快。

    [2:00-3:30] 场景对比演示¶

    【画面】 切到 VS Code，打开一个 Python 文件，逐步敲代码。

    【旁白】 光说不练假把式。我们直接用 API 对话数据来对比。

    先看列表——API 返回的 messages 就是一个列表，每个元素是一条消息的字典：

    messages = [
    {"role": "system", "content": "你是助手"},
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好！"},
]

    为什么用列表？因为消息有先后顺序，第一条是 system，第二条是 user。你能想象用字典存吗？messages[0]？不，字典是按 key 取的，消息没有自然的 key。所以——有顺序，用列表。

    再看字典——如果我要统计每个模型被调了几次，用字典天然合适：

    model_count = {"deepseek-chat": 3, "deepseek-reasoner": 2}
print(model_count["deepseek-chat"])  # 3

    key 是模型名，value 是次数。要映射、要计数、要分组，用字典。

    [3:30-5:00] 集合与元组的实战场景¶

    【画面】 继续在同一个文件中敲代码。运行结果实时显示在终端面板。

    【旁白】 集合最经典的场景是去重。假设我有一份 API 调用日志，里面有很多重复的模型名，我想知道一共用了哪些模型：

    models_used = ["deepseek-chat", "deepseek-chat", "deepseek-reasoner", "deepseek-chat"]
unique = set(models_used)
print(unique)  # {'deepseek-chat', 'deepseek-reasoner'}

    一行 set() 搞定。如果不用集合呢？你得遍历、判断在不在结果列表里、再 append——四五行代码。所以记住：去重找集合。

    元组最常见于函数返回多个值，或者 API 返回的固定结构：

    # API 返回的 usage 字段经常是元组式结构
api_info = ("deepseek-chat", 45, True)  # (模型名, token数, 是否成功)
model, tokens, success = api_info  # 一行解包三个值

    创建后不会被修改的数据，用元组。如果你不确定，用列表就好——元组在初学阶段用到的不多，遇到了能认出来就行。

    [5:00-6:30] 选型决策树¶

    【画面】 PPT 动画：一棵决策树——"有顺序？"→"要修改？"→"要去重？"→"要按 key 查？"四个分叉，每个分叉指向一种结构。

    【旁白】 我给你一张选型决策树，遇到数据往上一套就知道：

    第一问：数据有顺序吗？ 有 → 列表或元组；没有 → 字典或集合。

    第二问：要修改吗？ 要改 → 列表；不能改 → 元组。

    第三问：要按名字查吗？ 是 → 字典；只要去重 → 集合。

    就这么简单。API 消息列表有顺序要改 → 列表。模型调用计数要按名字查 → 字典。用户标签去重 → 集合。API 返回的固定元信息 → 元组。

    [6:30-7:45] 可运行闭环：对话数据全流程¶

    【画面】 回到 VS Code，运行一段完整代码，终端逐步打印输出结果。

    【旁白】 最后来一段完整闭环——用四种结构管理一次 API 对话数据：

    # ① 列表存有序消息
messages = []
messages.append({"role": "user", "content": "你好"})
messages.append({"role": "assistant", "content": "你好！有什么可以帮你？"})

# ② 字典做统计
stats = {"total_messages": len(messages), "user_count": 1}

# ③ 集合提取所有出现过的角色
roles = set(msg["role"] for msg in messages)
print("角色:", roles)

# ④ 元组存元信息
meta = ("deepseek-chat", len(messages))
print(f"模型: {meta[0]}, 消息数: {meta[1]}")

    运行——角色集合是 {'user', 'assistant'}，元信息一行解包。四种结构各司其职，这就是真实 AI 应用里数据管理的日常。

    [7:45-8:00] 小结 + 引出下集¶

    【画面】 字幕条总结四句口诀。然后切出下集预告画面。

    【旁白】 一句话记住：列表管顺序、字典管映射、元组管不变、集合管去重。

    【画面】 提问彩蛋。字幕条依次列出三个可以直接照抄去问 Kimi/DeepSeek 的 prompt：

    • ① 扮演数据结构面试官：连续给我 5 个真实开发场景，比如存聊天记录、统计词频、给用户标签去重，每给一个就问我该用列表、字典、元组还是集合，我答完再点评。
    • ② 我总搞混 Python 的列表、字典、元组、集合，请各给我一个"选错它会写得很痛苦"的真实例子，帮我建立直觉。
    • ③ 出 8 道数据结构选型题：每题给一组数据和需求，让我判断该用哪种结构，先只出题，我答完再公布答案并讲解。

    【旁白】 送你一个提问彩蛋——这三个 prompt 直接照抄去问 AI。选型这事，问它"这段数据用什么存"，它一秒给答案，但你下次还是不会。换个问法：让它出场景、你来选、它再点评，练几次判断力就长出来了。

    【旁白】 下集我们深入列表和字典的核心操作——增删改查怎么写，遍历怎么遍，我给你一张速查表，写代码时直接对着抄。

    演示操作清单¶

    完整演示代码（按视频顺序逐步敲入）¶

    # === V011 演示完整代码 ===

# --- Part 1: 列表——有序可变 ---
messages = [
    {"role": "system", "content": "你是助手"},
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好！"},
]
print("第一条消息:", messages[0])
print("消息总数:", len(messages))

# --- Part 2: 字典——键值映射 ---
model_count = {"deepseek-chat": 3, "deepseek-reasoner": 2}
print("deepseek-chat 调用次数:", model_count["deepseek-chat"])

# --- Part 3: 集合——去重 ---
models_used = ["deepseek-chat", "deepseek-chat", "deepseek-reasoner", "deepseek-chat"]
unique_models = set(models_used)
print("去重后:", unique_models)

# --- Part 4: 元组——不可变序列 ---
api_info = ("deepseek-chat", 45, True)
model, tokens, success = api_info
print(f"模型: {model}, tokens: {tokens}, 成功: {success}")

# --- Part 5: 选型决策树闭环 ---
# ① 列表存有序消息
chat_messages = []
chat_messages.append({"role": "user", "content": "你好"})
chat_messages.append({"role": "assistant", "content": "你好！有什么可以帮你？"})

# ② 字典做统计
stats = {"total_messages": len(chat_messages), "user_count": 1}

# ③ 集合提取所有出现过的角色
roles = set(msg["role"] for msg in chat_messages)
print("角色:", roles)

# ④ 元组存元信息
meta = ("deepseek-chat", len(chat_messages))
print(f"模型: {meta[0]}, 消息数: {meta[1]}")

    录制注意¶

    1. 易口误：说字典时容易说成"花括号是字典"——准确说法是"花括号 {} 创建字典，但空 {} 默认是字典不是集合，空集合要写 set()"。如果录制时口误了，在演示代码环节用 type({}) 和 type(set()) 做一个验证对比。
    2. 字幕条重点：四句话定位一定要出字幕条——"列表管顺序、字典管映射、元组管不变、集合管去重"，让观众截图就能复习。
    3. 预埋翻车点：在集合部分，故意先写 unique = {models_used}（套了一层），运行报错后再修正为 set(models_used)，展示初学者常见错误。但如果时长紧张可省略。
    4. 时长控制点：选型决策树（5:00-6:30）是核心干货，如果前面讲慢了，Part 4 元组可以压缩到 30 秒（只展示解包语法不展开讲），把时间留给决策树。
    5. 提问彩蛋字幕：提问彩蛋段的 prompt 字幕条需在后期加上，确保观众能暂停照抄。
