    一句话定位 大模型会"幻觉"——RAG 用 Embedding 向量做语义检索，让 AI 基于你的文档而非记忆来回答

    逐字稿¶

    [0:00-0:35] 开场 hook：幻觉时刻——AI 自信地编了一个答案¶

    【画面】 终端中运行一段代码，问 DeepSeek："《Python程序设计》这门课的期末项目占多少分？" AI 自信地回答"期末项目占总成绩的 40%"。画面定格，红色大字覆盖："❌ 正确答案是 50%"。然后切换到另一段代码——把课程评分标准文档拼进 prompt 后再问同一个问题，AI 回答"期末大项目占总成绩的 50%"。绿色对勾覆盖。字幕条："同一个问题 · 没文档时 AI 编 · 有文档时 AI 对"。

    【旁白】 看这个。我问 AI"这门 Python 课的期末项目占多少分"——它非常自信地说"占 40%"。但正确答案是 50%。AI 根本不知道你们这门课的信息，它是编的。这就是大模型的"幻觉"问题。但如果我把课程文档喂给它再问同一个问题——回答完全正确。从编造到准确，中间用的技术叫 RAG，就是今天这集的主题。

    [0:35-2:00] 大模型的两大局限与 RAG 的基本思路¶

    【画面】 PPT 展示大模型的两个短板。第一个："知识截止——训练数据有截止日期，之后的事不知道"。第二个："幻觉——不知道的问题也'自信'回答"。下方出现传统方案的对比：左侧"微调"标注"太贵太难"；右侧"RAG（检索增强生成）"标注"检索文档 → 拼入 prompt → AI 基于文档回答"。中间出现一个类比图标：闭卷考试 📵 → 开卷考试 📖。

    【旁白】 大模型有两个天生的短板。

    第一，知识截止。模型的训练数据有截止日期，训练之后发生的事它不知道。你们这门课的大纲、考核方式——训练时没见过，它当然不知道。

    第二，幻觉。不知道的问题它不会说"我不知道"，而是编一个看起来合理但实际错误的答案。刚才那个"40%"就是典型的幻觉。

    传统解决方案是微调——用你的数据重新训练模型。但微调太贵、太难，不适合日常开发。

    RAG 换了个思路。打个比方：大模型是闭卷考试——背了很多但不一定准。RAG 是开卷考试——考试时先翻到相关资料，再照着资料答题。具体来说三步：第一步检索，从你的文档里找到和问题最相关的内容；第二步拼接，把检索到的内容拼进 prompt；第三步生成，让 AI 基于你给的资料回答。AI 不再靠记忆，而是有据可依。

    [2:00-3:30] Embedding：把文本变成向量¶

    【画面】 PPT 动画。一段文字"本课程成绩由平时作业和期末项目组成"经过一个箭头标注"Embedding API"，变成一串数字 [0.12, -0.34, 0.56, ...]，标注"1024维向量"。旁边另一段文字"虚拟环境用 pipenv 管理"也变成一串数字。两串数字之间画一条线，标注"语义近 → 向量距离近"。再放一段"Python 列表是有序序列"的向量，与第一段之间画一条远距离的虚线，标注"语义远 → 向量距离远"。

    【旁白】 RAG 第一步是检索，核心靠 Embedding。

    Embedding 就是把文本变成一串数字，专业说法叫向量。你可以理解为——它给每段文本标了一个"语义坐标"。意思相近的文本，坐标也近；意思无关的文本，坐标很远。

    比如"课程成绩由作业和项目组成"和"考试怎么评分"——字面不一样，但意思相近，它们的向量距离就很近。而"课程成绩"和"虚拟环境管理"——八竿子打不着，向量距离就很远。

    Embedding 通过调用 API 实现。你把文本传进去，API 返回一个通常 1024 或 1536 维的浮点数列表。这就是文本的"语义指纹"。你不需要关心这些数字具体怎么算出来的——你只需要知道，语义相近的文本，向量距离也近。这就是语义检索的基础。

    [3:30-5:00] 余弦相似度：用 numpy 衡量向量距离¶

    【画面】 VS Code 中展示 cosine_similarity 函数。用高亮标注三行：np.dot 点积、np.linalg.norm 向量长度、除法。右侧放一个直观图——两个箭头从原点出发，夹角小标注"相似度高（≈1）"，夹角大标注"相似度低（≈0）"。

    【旁白】 文本变成向量后，怎么比较"远近"？用余弦相似度。

    原理不展开数学推导，你只需要记住一个直觉：把两个向量想象成两支箭——方向越一致，相似度越高，最大值是 1；方向越远离，相似度越低。

    用 numpy 实现只要三行：

    import numpy as np

def cosine_similarity(vec_a, vec_b):
    dot = np.dot(vec_a, vec_b)
    norm_a = np.linalg.norm(vec_a)
    norm_b = np.linalg.norm(vec_b)
    return dot / (norm_a * norm_b)

    np.dot 算点积，np.linalg.norm 算向量长度，除一下就是余弦相似度。返回值在 0 到 1 之间——越接近 1 越相似。这个函数你现在不用深究推导，记住"输入两个向量，输出一个 0 到 1 的数，越大越相似"就够了。

    [5:00-7:00] 可运行闭环：语义检索 demo¶

    【画面】 VS Code 展示 semantic_search.py。先展示文档库（6 条课程相关文本），然后展示 get_embedding 函数调用 API，再展示检索逻辑：问题向量化 → 逐个算相似度 → 排序 → 取 top-3。终端运行，查询"这门课怎么评分的？"，展示每条文档的相似度分数和最终排名。

    【旁白】 来写一个能跑的语义检索。不用任何框架，就 openai SDK 加 numpy。

    先准备一个小文档库——6 条课程相关的文本，包括评分标准、作业说明、模块结构等。

    然后写 get_embedding 函数，调用 Embedding API，把文本变成 numpy 数组返回。接口和调用聊天 API 很像——传 model 和 input，返回值在 response.data[0].embedding。

    核心检索逻辑：用户问题"这门课怎么评分的？"先做 Embedding 变成向量，然后和每条文档的向量算余弦相似度，最后按相似度降序排列，取前 3 条。

    运行看效果。"这门课怎么评分的"——最相关的是"本课程成绩由平时作业50%和期末大项目50%组成"，相似度 0.89。第二条是"平时作业包括4次小作业"，相似度 0.72。

    注意一个关键点：查询里没有出现"成绩"两个字，用的是"评分"。但语义检索照样找到了正确答案。如果是关键词检索，它只会匹配"评分"这个词——而文档里写的是"成绩"，就匹配不上。这就是语义检索比关键词检索强的地方——它理解意思，不只是匹配字面。

    [7:00-7:45] 关键词检索 vs 语义检索的对比¶

    【画面】 PPT 对比表格。左列"关键词检索"：精确匹配字面，搜索"评分"只能找到包含"评分"这个词的文档，搜不到写"成绩"的文档。右列"语义检索"：理解意思，搜"评分"能找到写"成绩"的文档。底部标注："RAG 选择语义检索——因为用户问问题和文档写的方式往往字面不同但意思相同"。

    【旁白】 总结一下检索方式的对比。

    关键词检索就是 Python 的 in 操作——看"评分"这个词在不在文档里。简单粗暴，但问题在于：用户问"怎么评分"和文档写的"成绩占比"——意思一样，字面不同，关键词检索就找不到。

    语义检索通过 Embedding 理解意思——"评分"和"成绩"在语义空间里是近的，所以能匹配上。RAG 选择语义检索，正是因为用户提问的方式和文档的表述方式往往字面不同。

    当然关键词检索也有优势——精确匹配场景，比如搜索代码里的函数名，关键词检索更靠谱。技术没有银弹，但在 RAG 场景下，语义检索是主流选择。

    [7:45-8:00] 小结¶

    【画面】 字幕条："大模型有幻觉 · RAG = 检索 + 拼接 + 生成 · Embedding 把文本变向量 · 余弦相似度衡量语义距离"。

    【旁白】 核心记住几件事：大模型有幻觉和知识截止两大短板；RAG 的思路是检索文档 → 拼接 prompt → 让 AI 有据可依；Embedding 把文本变成向量，语义相近的文本向量也近；余弦相似度用 numpy 三行代码就能算。

    [8:00-8:20] 提问彩蛋¶

    【画面】 黑底字幕条逐条弹出三个 prompt（右上角标注"暂停照抄"）： 1. 「我在学 RAG（检索增强生成）。请扮演面试官追问我：大模型为什么会产生幻觉？RAG 的"检索、拼接、生成"三步分别解决什么问题？」 2. 「给我出 3 道判断题：每题给一个检索场景，让我判断关键词检索和语义检索哪个更合适，我答完你讲解——至少有一题的答案应该是关键词检索。」 3. 「用"开卷考试"的类比给我讲透 Embedding 和余弦相似度，全程不许出现数学公式，最后解释清楚：为什么搜"评分"能匹配到写"成绩"的文档？」

    【旁白】 彩蛋来了——三个 prompt 直接抄。RAG 概念多、听着抽象，正好让 AI 用类比给你讲透，再让它扮演面试官把你问倒。学习的窍门不是多要答案，而是让 AI 帮你找出那些"你以为你懂了"的地方。

    # semantic_search.py —— 语义检索 demo（不用 LangChain 等框架）
"""文档库 → Embedding → 余弦相似度 → top-k 检索"""
import os
import numpy as np
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

client = OpenAI(
    api_key=os.environ.get("DEEPSEEK_API_KEY", ""),
    base_url="https://api.deepseek.com"
)

# ---- 文档库 ----

DOCUMENTS = [
    "本课程成绩由平时作业（50%）和期末大项目（50%）组成，无上机考试。",
    "平时作业包括4次小作业（各占10%）和课堂参与（10%）。",
    "作业④是 Prompt 工程实战，要求设计结构化 prompt 模板。",
    "M5 AI应用开发模块共12节课，从大模型 API 深入到 Agent 实战。",
    "期末项目以 2-3 人分组形式完成，需包含前端、后端和 AI 核心功能。",
    "虚拟环境管理推荐 pipenv 或 conda，每个项目一个独立环境。",
]


# ---- Embedding ----

def get_embedding(text: str) -> np.ndarray:
    """调用 Embedding API，把文本变成向量"""
    response = client.embeddings.create(
        model="deepseek-embed",   # 以实际可用模型名为准
        input=text
    )
    return np.array(response.data[0].embedding)


# ---- 余弦相似度 ----

def cosine_similarity(vec_a, vec_b) -> float:
    """计算两个向量的余弦相似度（0~1，越大越相似）"""
    return np.dot(vec_a, vec_b) / (np.linalg.norm(vec_a) * np.linalg.norm(vec_b))


# ---- 语义检索 ----

def search(query: str, documents: list, top_k: int = 3) -> list:
    """检索与 query 最相关的 top_k 条文档"""
    print(f"正在生成 embedding...")
    query_vec = get_embedding(query)

    scores = []
    for i, doc in enumerate(documents):
        doc_vec = get_embedding(doc)
        score = cosine_similarity(query_vec, doc_vec)
        scores.append((i, doc, score))

    scores.sort(key=lambda x: x[2], reverse=True)

    print(f"\n查询: {query}")
    print("-" * 60)
    for idx, doc, score in scores:
        print(f"  [{score:.4f}] {doc[:40]}...")

    return scores[:top_k]


# ---- 运行 ----

if __name__ == "__main__":
    results = search("这门课怎么评分的？", DOCUMENTS, top_k=3)
    print(f"\n最相关: [{results[0][2]:.4f}] {results[0][1]}")

    注意：DeepSeek 的 Embedding 模型名称以官方文档为准。如 DeepSeek 暂不提供 Embedding 接口，可改用智谱 GLM（base_url="https://open.bigmodel.cn/api/paas/v4"，model="embedding-3"）或其他 OpenAI 兼容的 Embedding 服务。核心代码结构完全一致。

    录制注意¶

    1. 开场幻觉演示必须真实运行：开场 30 秒展示的两次 API 调用必须实际跑通——第一次不带文档让 AI 编造，第二次带文档让 AI 准确回答。两个对比放在同一画面中，让观众一眼看到"有没有文档"的巨大差异。
    2. Embedding 概念用动画辅助：文本变成向量这个过程比较抽象，建议用 PPT 动画展示——文字 → 箭头 → 数字串，再标注"语义近→向量近"。不要只口播，视觉化才能让零基础观众理解。
    3. 余弦相似度不展开数学：严格控制在"输入两个向量，输出 0 到 1 的数，越大越相似"的认知层面。不要推导公式，不要解释点积的几何意义。数学细节交给课后和 AI 辅助。
    4. 语速控制：整体旁白约 1900 字，按 235 字/分钟控制在 8 分钟以内。Embedding 和相似度讲解适当放慢，开场和结尾正常语速。
    5. 提问彩蛋段的 prompt 字幕条需在后期加上，确保观众能暂停照抄。
