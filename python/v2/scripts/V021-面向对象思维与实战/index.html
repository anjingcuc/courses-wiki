    [0:00-0:30] 开场 hook（成果前置）¶

    【画面】 屏幕上并排展示两个终端窗口——左边是"翻译助手"在回复 Hello, World，右边是"编程助手"在回复 列表推导式是...。两个窗口各自独立运行，互不影响。字幕条："两个 AI 助手，互不干扰"。

    【旁白】 上节课学了类的语法——class、__init__、self。但知道语法不等于知道什么时候该用。今天直接看一个真实场景：同时开两个 AI 聊天助手，一个帮你翻译，一个帮你写代码，各自独立对话，互不干扰。用函数能做到吗？能，但你会疯。用类？创建两个实例就行。

    [0:30-2:15] 什么时候该用类¶

    【画面】 左右分屏对比：左边"散装函数写法"——chat() 函数参数列表有 5 个参数，调用时传来传去，旁边红色标注"容易传错"；右边"类写法"——参数存在 self 上，方法直接用，旁边绿色标注"自动绑定"。字幕条："数据+操作绑定 → 用类"。

    【旁白】 先回答最关键的问题——什么时候该用类？

    判断标准很简单：当一组数据和操作这组数据的函数高度耦合时，用类封装。高度耦合的意思是——这些数据总是被这组函数一起使用，分不开。

    来看之前课里的散装写法。调用一次大模型 API 你需要什么？api_key、model、system_prompt，还有对话历史 history。如果用函数，每次调用 chat() 都要把这几个参数传进去：

    # 散装函数写法——参数多、容易乱
reply = chat(api_key, model, history, system_prompt, "你好")

    参数列表又长又容易搞混——你可能会把 history 和 system_prompt 的顺序写反。而且拿到回复后，更新后的 history 怎么传出来？函数内部修改了全局变量？还是返回一个元组让你解包？怎么写都觉得别扭。

    换成类的写法，一切问题消失——数据存在 self 上，方法通过 self 直接访问，不用参数传来传去：

    # 类的写法——数据和行为绑在一起
manager = AIChatManager(api_key="sk-xxx", system_prompt="翻译助手")
reply = manager.send("你好")
# history 自动存在 manager 对象里，下次 send 自动带上

    创建实例时传一次参数，之后 send 方法自动用 self 访问所有数据。清爽、干净、不会传错。

    什么时候**不**该用类？如果你只是写个一次性的数据处理脚本——读个文件、算个结果、打印输出——几个函数搞定的事，用函数就够了。别为了用类而用类，那叫过度设计，反而让代码更难读。

    什么时候**该**用类？两个信号：第一，数据需要"记住"——对话历史就是状态，跨多次调用要持续维护；第二，同一套逻辑需要多份独立副本——比如两个聊天窗口各自独立。满足任意一个，就该考虑类了。

    [2:15-4:15] 两个实例互不干扰¶

    【画面】 VS Code 中展示 AIChatManager 类定义，然后创建两个实例 translator 和 coder，分别调用 send 方法。运行后终端输出两个管理器各自的 history 长度和内容摘要。高亮 translator 和 coder 两个变量名，用不同颜色区分。

    【旁白】 现在来看类最强大的实战特性——每个实例独立维护自己的状态。

    上节课我们定义了 AIChatManager 类。现在直接创建两个实例：

    translator = AIChatManager(
    api_key="sk-xxx",
    system_prompt="你是一个翻译助手，把中文翻译成英文"
)

coder = AIChatManager(
    api_key="sk-xxx",
    system_prompt="你是一个Python编程助手，简洁回答"
)

    translator 和 coder 都是 AIChatManager 类的实例，都拥有相同的属性和方法。但关键在于——它们的 system_prompt 不同，history 各自独立。用上节课的话说：同一个图纸，盖了两栋不同的房子。

    开始各自对话：

    translator.send("你好")
coder.send("什么是列表推导式")

translator.send("谢谢")
coder.send("再举个例子")

    translator 发的消息只存到 translator.history，coder 发的消息只存到 coder.history。为什么？因为每次调用 send 方法时，self 指向的是不同的实例。translator 调用时 self 就是 translator，coder 调用时 self 就是 coder。两个对象互不干扰，就像两个独立的聊天窗口。

    来看运行结果：

    print(f"翻译助手历史: {len(translator.history)} 条")
print(f"编程助手历史: {len(coder.history)} 条")

    翻译助手 5 条——一条 system 提示加两轮对话，每轮一条用户消息加一条 AI 回复。编程助手也是 5 条，结构一样但内容完全不同。各自独立，清清楚楚。如果这时候给翻译助手再发一条消息，它的历史变 7 条，编程助手还是 5 条。

    如果用散装函数呢？你得维护 history_translator 和 history_coder 两套变量，每次调用 chat() 还得确保传对参数——传错了两个窗口的对话就串了。写两个窗口就够乱了，三个、四个呢？用类——创建几个实例的事。这就是类的核心价值：用一份代码管理多份独立状态。

    [4:15-5:30] 继承概念速览¶

    【画面】 PPT 动画：AIChatManager 作为父类，向下延伸出 ReasoningChatManager 子类。子类继承了 send、show_history 方法（灰色标注"继承而来"），同时改了 model 为 deepseek-reasoner（高亮标注"自己的修改"）。super() 用箭头指向父类的 init。

    【旁白】 类还有一个重要特性——继承。你现在不用会写复杂的继承体系，但**读代码时要能看懂**，因为以后用第三方库到处都是继承。

    继承的概念很简单——子类继承父类的所有属性和方法，不用重新定义就能直接用，同时还能扩展自己的特性。

    来看例子。我们之前写的 AIChatManager 默认用的是 deepseek-chat 模型。现在想要一个专门用推理模型的版本——deepseek-reasoner。不用重新写一个完整的类，继承就行：

    class ReasoningChatManager(AIChatManager):
    """继承AIChatManager，使用推理模型"""

    def __init__(self, api_key, system_prompt):
        super().__init__(
            api_key=api_key,
            system_prompt=system_prompt,
            model="deepseek-reasoner"
        )

    类名后面括号里的 (AIChatManager) 表示继承关系——ReasoningChatManager 是子类，AIChatManager 是父类。

    子类自动继承了父类的 send、show_history 所有方法，不用再写一遍。它唯一改动的是初始化时把 model 换成了 deepseek-reasoner。super().__init__(...) 这行是关键——super 代表父类，调用父类的 __init__ 方法，把 api_key、system_prompt 这些公共初始化逻辑复用过来。你只需要写"不同的部分"——在这里就是换个模型名。

    以后读别人代码看到 class XXX(YYY):，就知道 XXX 继承了 YYY。FastAPI、Pydantic 这些库你以后都会用到继承——到时候回来复习这段就够了。

    [5:30-6:30] 可运行闭环：两个独立助手¶

    【画面】 屏幕展示完整代码并运行。终端依次输出：翻译助手两轮对话的结果、编程助手两轮对话的结果，最后分别打印两个管理器的 history 条数。两个管理器用不同颜色标注。

    【旁白】 来看今天的完整闭环——两个独立的 AI 助手同时运行：

    from openai import OpenAI


class AIChatManager:
    """AI对话管理器——封装API配置和对话历史"""

    def __init__(self, api_key, system_prompt, model="deepseek-chat", base_url="https://api.deepseek.com"):
        self.client = OpenAI(api_key=api_key, base_url=base_url)
        self.model = model
        self.history = [
            {"role": "system", "content": system_prompt}
        ]

    def send(self, user_input):
        self.history.append({"role": "user", "content": user_input})
        try:
            response = self.client.chat.completions.create(
                model=self.model,
                messages=self.history
            )
            reply = response.choices[0].message.content
            self.history.append({"role": "assistant", "content": reply})
            return reply
        except Exception as e:
            self.history.pop()
            return f"调用失败: {e}"

    def show_history(self):
        for msg in self.history:
            print(f"  [{msg['role']}] {msg['content'][:40]}")


# --- 创建两个独立助手 ---
translator = AIChatManager(
    api_key="sk-xxx",
    system_prompt="你是一个翻译助手，把中文翻译成英文"
)
coder = AIChatManager(
    api_key="sk-xxx",
    system_prompt="你是一个Python编程助手，简洁回答"
)

# --- 各自独立对话 ---
print("=== 翻译助手 ===")
print("AI:", translator.send("你好，世界"))
print("AI:", translator.send("今天天气真好"))

print("\n=== 编程助手 ===")
print("AI:", coder.send("什么是列表推导式"))
print("AI:", coder.send("写个求平方的例子"))

# --- 验证互不干扰 ---
print(f"\n翻译助手历史: {len(translator.history)} 条")
print(f"编程助手历史: {len(coder.history)} 条")

    运行。翻译助手收到"你好，世界"返回 Hello, World，收到"今天天气真好"返回 The weather is nice today。编程助手收到"什么是列表推导式"返回一段简洁解释，收到"写个求平方的例子"返回一段代码。两个助手各聊各的，互不干扰。

    最后打印两个管理器的 history 条数——都是 5 条。一份类定义，两份独立状态。如果给翻译助手再加一轮对话，它变成 7 条，编程助手不受影响，还是 5 条。这就是面向对象在真实场景中的威力。

    [6:30-7:00] 小结¶

    【画面】 字幕条："数据+操作绑定 → 用类 · 多个实例各自独立 · 继承 = 子类扩展父类"。然后展示 M2 六课的全景图——L6 数据类型 → L7 数据结构 → L8 控制流 → L9 函数 → L10 文件/异常/模块 → L11 类。一个箭头从 L11 指向右侧的 M3"数据获取与处理"。

    【旁白】 三句话总结今天的面向对象思维——第一，数据加操作高度绑定就用类；第二，多个实例各自独立互不干扰，这是类最大的实战价值；第三，继承就是子类复用并扩展父类，读代码时能看懂就行。

    完整演示代码¶

    # === V021 演示完整代码 ===
from openai import OpenAI


class AIChatManager:
    """AI对话管理器——封装API配置和对话历史"""

    def __init__(self, api_key, system_prompt, model="deepseek-chat", base_url="https://api.deepseek.com"):
        self.client = OpenAI(api_key=api_key, base_url=base_url)
        self.model = model
        self.history = [
            {"role": "system", "content": system_prompt}
        ]

    def send(self, user_input):
        """发送消息并获取AI回复"""
        self.history.append({"role": "user", "content": user_input})
        try:
            response = self.client.chat.completions.create(
                model=self.model,
                messages=self.history
            )
            reply = response.choices[0].message.content
            self.history.append({"role": "assistant", "content": reply})
            return reply
        except Exception as e:
            self.history.pop()
            return f"调用失败: {e}"

    def show_history(self):
        """打印对话历史摘要"""
        for msg in self.history:
            print(f"  [{msg['role']}] {msg['content'][:40]}")


# --- 创建两个独立助手 ---
translator = AIChatManager(
    api_key="sk-xxx",
    system_prompt="你是一个翻译助手，把中文翻译成英文"
)
coder = AIChatManager(
    api_key="sk-xxx",
    system_prompt="你是一个Python编程助手，简洁回答"
)

# --- 各自独立对话 ---
print("=== 翻译助手 ===")
print("AI:", translator.send("你好，世界"))
print("AI:", translator.send("今天天气真好"))

print("\n=== 编程助手 ===")
print("AI:", coder.send("什么是列表推导式"))
print("AI:", coder.send("写个求平方的例子"))

# --- 验证互不干扰 ---
print(f"\n翻译助手历史: {len(translator.history)} 条")
print(f"编程助手历史: {len(coder.history)} 条")

print("\n--- 翻译助手完整历史 ---")
translator.show_history()
print("\n--- 编程助手完整历史 ---")
coder.show_history()
