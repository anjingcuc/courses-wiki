### [0:30-3:00] Few-shot Learning：示范比描述更有效

**【画面】** VS Code 中展示情感分类的两种 prompt。先运行零样本版，终端输出一段分析文字；再运行 Few-shot 版，终端只输出一个词"正面"。

**【旁白】** 先看 Few-shot。

场景——做一个情感分类器，判断评论是正面、负面还是中性。

先试零样本——也就是不给任何示例，直接描述任务：

```python
from llm_utils import llm_chat

prompt_zero = """判断以下评论的情感，输出"正面"、"负面"或"中性"：

评论：这家店的菜品分量很足，味道也不错，就是上菜有点慢。"""

print("=== 零样本 ===")
print(llm_chat(prompt_zero, temperature=0))
```

跑一下——输出可能是"正面"，但也可能是一段分析文字"这条评论整体偏正面，因为……"。AI 不确定你想要什么格式——你说"输出正面负面中性"，但它觉得"解释一下更全面"。

现在加 Few-shot——给 3 个"输入→输出"示例：

```python
prompt_few = """判断评论的情感。

示例：
评论：这个手机续航太差了，半天就没电。
情感：负面

评论：服务态度很好，环境也不错，推荐！
情感：正面

评论：价格一般，位置在地铁站旁边。
情感：中性

现在判断这条评论：
评论：这家店的菜品分量很足，味道也不错，就是上菜有点慢。
情感："""

print("=== Few-shot ===")
print(llm_chat(prompt_few, temperature=0))
```

跑一下——输出就一个词：`正面`。格式完全匹配。

为什么差别这么大？因为 **Few-shot 的本质是"示范而非描述"**——与其费口舌描述"我要什么格式"，不如直接给几个例子。AI 的模式匹配能力极强，看到 3 个"评论→情感"的对应关系，它就知道——你要的不是一个分析报告，就一个词。

**核心心法：示例是教 AI 做什么。** 3 个精心设计的示例就够了，不需要堆十几个。示例不在多，在于有代表性——正面、负面、中性各一个，覆盖你要的所有输出类别。

### [3:00-5:15] Chain of Thought：教 AI 一步一步想

**【画面】** PPT 动画展示一道数学题。左半边——直接提问，AI 直接给答案（偶尔算错）。右半边——CoT 提问，AI 逐步列出推理过程。字幕条："CoT 不是让 AI 算得更准，而是让它暴露推理过程"。

**【旁白】** 再来看第二个技巧——Chain of Thought，思维链，简称 CoT。

场景——一道需要推理的数学题：

```python
prompt_direct = """小明有 15 个苹果，给了小红一半，又买了 8 个，然后吃了 3 个。
小明现在有几个苹果？"""
```

直接问——AI 可能直接给答案。但简单数学对大模型来说反而容易出错，因为它本质是在做"下一个 token 预测"，不是在做真正的算术。

换 CoT 提问——引导它一步一步推理：

```python
prompt_cot = """小明有 15 个苹果，给了小红一半，又买了 8 个，然后吃了 3 个。
小明现在有几个苹果？

请一步一步分析：
1. 先算给了小红多少
2. 再算给了之后剩多少
3. 买了之后多少
4. 吃了之后多少"""

print("=== CoT ===")
print(llm_chat(prompt_cot, temperature=0))
```

这次 AI 会把每一步推理都列出来——给了多少、剩多少、买了之后多少、吃了之后多少——最后给答案。你能清楚地看到它每一步算的是什么，哪里出了问题一目了然。

这里有个关键认知——**CoT 不是让 AI 算得更准，而是让它把推理过程暴露出来。** 对于复杂推理任务——逻辑分析、代码审查、方案设计——CoT 能显著提升输出质量。因为大模型在做"逐步推理"时，每一步的预测都有前面的步骤作为上下文，比直接跳到最终答案要靠谱得多。

CoT 不一定要手写推理步骤。DeepSeek 的 `deepseek-reasoner` 模型内置了思维链——它会自动展示推理过程，不需要你在 prompt 里加"请一步一步分析"。如果你的任务涉及复杂推理，直接用 reasoner 模型就行。

### [5:15-5:45] 核心心智模型

**【画面】** PPT 展示一张对比图——左边"Few-shot：示例 → 教 AI 做什么"，右边"CoT：推理步骤 → 教 AI 怎么想"。中间一行字："两个技巧可以叠加使用"。

**【旁白】** 最后把两个技巧放在一起对比——记住一句话心智模型：

**Few-shot 是教 AI 做什么——给它看几个例子，它模仿你的格式和模式。**
**CoT 是教 AI 怎么想——引导它逐步推理，暴露思考过程。**

两者不冲突——你可以给 AI 几个带推理过程的示例，同时教它"做什么"和"怎么想"。在实际项目中，先用 Few-shot 锁定输出格式，再用 CoT 提升推理质量，这是最常见的组合拳。

### [5:45-6:45] 可运行闭环：Few-shot 情感分类器

**【画面】** VS Code 中运行 `few_shot_demo.py`，先跑零样本、再跑 Few-shot，终端并排展示两次输出差异。

**【旁白】** 最后看一个完整闭环——Few-shot 情感分类器，对比零样本和 Few-shot 的输出差异：

```python
# few_shot_demo.py
from llm_utils import llm_chat

review = "这家店的菜品分量很足，味道也不错，就是上菜有点慢。"

# 零样本
prompt_zero = f'判断以下评论的情感，输出"正面"、"负面"或"中性"：\n\n评论：{review}'

# Few-shot：3 个示例 + 1 个待判断
prompt_few = f"""判断评论的情感。

示例：
评论：这个手机续航太差了，半天就没电。
情感：负面

评论：服务态度很好，环境也不错，推荐！
情感：正面

评论：价格一般，位置在地铁站旁边。
情感：中性

现在判断这条评论：
评论：{review}
情感："""

print("=== 零样本 ===")
print(llm_chat(prompt_zero, temperature=0))

print("\n=== Few-shot ===")
print(llm_chat(prompt_few, temperature=0))
```

运行——零样本可能输出一段分析，Few-shot 精准输出"正面"。同一段评论、同一个模型，3 个示例就改变了输出的精准度。这就是 Few-shot 的价值。

### [6:45-7:00] 小结

**【画面】** 字幕条："Few-shot → 教 AI 做什么 · CoT → 教 AI 怎么想"。

**【旁白】** 总结——Few-shot 用示例教 AI 做什么，CoT 用推理步骤教 AI 怎么想。两个技巧加上五组件骨架，你的 prompt 就有了完整的结构。

# cot_demo.py —— Chain of Thought 推理演示

## 录制注意

1. **零样本 vs Few-shot 的输出对比是本集核心视觉冲击**：录制前先跑几次并截图保存。重点让观众看到"零样本可能输出一段分析，Few-shot 精准输出一个词"。如果现场 API 恰好零样本也输出了一个词，就用预录截图展示"不确定格式"的风险。
2. **temperature=0 要强调**：情感分类是确定性任务，temperature 设 0 让输出稳定可复现。录制时用光标指到 `temperature=0` 说明这一点。
3. **CoT 演示点到为止**：CoT 不在这节课展开讲太多实现细节，重点是建立"示例教做什么、CoT 教怎么想"的心智模型。`deepseek-reasoner` 只提一句，不展开演示——那是进阶内容。
