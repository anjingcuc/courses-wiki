第一步：需求与 MVP

项目提案四件套
  • 用户画像：谁在用？什么场景？
  • 核心功能清单：解决什么问题
  • 技术选型：对话 / RAG / Agent / 多模态，各用在哪、为什么
  • 分工计划：谁做什么、什么节奏
MVP 思维：砍功能
  • 「必须有」：没有它项目就不成立的核心闭环
  • 「有了更好」：先全部划掉
三周里最大的风险是「什么都想做」——先保住可交付的闭环。

课堂互动：「一句话电梯演讲」——谁用、解决什么问题、怎么解决。同学和教师现场追问。

冲刺一：本周开发目标

唯一目标：后端 API 能跑通，AI 核心功能能调通。前端下周再做。
检查点 1（上半场）
  • FastAPI 能启动
  • 至少一个端点在 /docs 测试通过
  • LLM 调用成功（不是占位符）
检查点 2（下半场）
  • AI 核心链路跑通（RAG 检索 / 工具调用）
  • 核心逻辑封装进 modules/，与路由解耦
  • 今天代码已 push 到 GitLab

开发纪律（贴在工位）

纪律一一次一个模块——prompt 拆小，不甩整个项目给 AI
纪律二大改前先 commit——随时可回退
纪律三每步验证——AI 写完马上运行，不攒一堆再测
纪律四不懂的代码不放过——答辩要指行讲解

Standup 节奏：每次开课每组 1–2 分钟——昨天做了什么 / 今天做什么 / blocker 是什么。
