FastAPI：六行代码一个服务

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class ChatRequest(BaseModel):        # 请求体结构（自动校验）
    message: str

@app.post("/chat")                    # 路由 = URL 与函数的绑定
async def chat(req: ChatRequest):
    return {"reply": await call_llm(req.message)}

# 启动：uvicorn main:app --reload   然后打开 /docs 看自动文档
  • 核心概念：路由（@app.post）+ Pydantic 模型（类型标注自动生成文档）
  • 三种参数：路径参数 /chat/{id}、查询参数 ?model=x、请求体（POST JSON）
  • async def：等 LLM 响应时不阻塞，单进程也能服务多个请求

前端最小集：HTML 三件套 + fetch

<div id="msgs"></div>  <input id="inp">  <button onclick="send()">发送</button>

async function send() {                 // 和 Python 的 async/await 概念相同
  const r = await fetch("/chat", {
    method: "POST",
    headers: {"Content-Type": "application/json"},
    body: JSON.stringify({message: inp.value})
  });
  const data = await r.json();
  msgs.innerHTML += `<p>AI: ${data.reply}</p>`;  // DOM 操作显示回复
}
  • HTML 搭骨架、CSS 穿衣服、JS 做交互——前端 UI 是 AI 最擅长的领域，给接口定义就能生成
  • 前后端数据流：前端发请求 → 后端调 LLM → 返回 JSON → 前端渲染

前后端联调三大坑

① CORS 报错 浏览器跨域安全机制——在后端加 CORSMiddleware 明确 allow_origins，不是绕开机制。
② 字段不匹配 后端返回 reply，前端读 answer → undefined。对着接口文档逐字核对。
③ 类型转换 JSON 里的数字到了前端是 string——该 Number() 的地方别偷懒。

async 事件循环
协程是怎么被调度的

正课的端点为什么写 async def？await 到底「等」的是什么？ 这 4 页用餐厅点餐和调度时间轴讲清事件循环——FastAPI 快的真正原因。

对应正课 W13 · M5 AI 应用开发约 10 分钟 · 按 → 逐条展开

同步 vs 异步：餐厅点餐

同步：一根筋服务员 给 A 桌点完单，杵在厨房门口死等，B、C 两桌干瞪眼。
A 桌
点单→死等→上菜
B 桌
终于轮到
C 桌
排队到打烊
总耗时 = 三桌串行相加——服务员大量时间在「等」。
异步：机灵服务员 给 A 下单后立刻去 B、C；谁的菜好了就端给谁。
A 桌
下单上菜
B 桌
下单上菜
C 桌
下单上菜
厨房（IO）忙的时候服务员（CPU）从不空等——一半时间就服务完三桌。

事件循环时间轴：谁让出，谁顶上

协程 A
计算await 等 LLM（让出）恢复
协程 B
排队计算await（让出）恢复
CPU
永不空转：A → B → 别人的请求 → A → …
  • await = 主动让出：「我要等网络/磁盘了，控制权还给事件循环」
  • 事件循环 = 调度员：登记每个协程在等什么，谁的结果到了就喊谁从断点继续
  • 注意：这是单线程内的接力——不是多线程，没有锁和竞态

async / await 与事件循环的对应

async def chat(msg):            # 定义协程——光调用不执行，只拿到「计划」
    r = await call_llm(msg)    # ① await：挂起点，控制权还给事件循环
    return r                    # ② 响应到达后，从这里原地恢复

await asyncio.gather(chat(a), chat(b), chat(c))   # 三个并发跑
  • async def 定义的是「可暂停的函数」；await 标出让出点——其余语法和你写过的一样
  • gather 把多个协程一起交给事件循环——总耗时 ≈ 最慢的那个，而不是相加
  • 坑：在协程里调同步阻塞函数（如 time.sleep、requests.get）会把整个事件循环卡死——要用对应的异步库

FastAPI 为什么快

  • 等 LLM 的 3–8 秒里，单进程转身去服务别人的请求——一台机器顶过去一排
  • AI 应用是典型的 IO 密集场景：网络调用占 95% 时间——async 收益最大
  • 边界：CPU 密集任务（图像处理、大矩阵运算）async 帮不上忙——那是多进程的事
