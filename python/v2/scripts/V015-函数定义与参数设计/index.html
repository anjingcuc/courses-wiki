    逐字稿¶

    [0:00-0:35] 开场 hook（痛点共鸣）¶

    【画面】 屏幕上展示一段 40 行的"面条代码"——所有逻辑平铺在文件顶层，没有函数。然后画面一转，同样的逻辑被拆成 3 个整洁的函数，主逻辑只有 5 行。字幕条："40 行面条代码 → 3 个函数 + 5 行主逻辑"。

    【旁白】 看这段代码——API 消息构建、调用、提取回复、统计 token，全堆在一起 40 行。想换一份数据再跑一次？复制粘贴 40 行。想改个参数？全局搜索半小时。这不是写代码，这是织毛衣——拆一根线全散了。

    函数就是给你的逻辑起个名字，之后喊名字就能用。今天教你 def 定义函数 + 函数契约四要素。学完这段，你的代码从"面条"变成"乐高积木"。

    [0:35-2:00] def 基本语法¶

    【画面】 VS Code 中逐步敲入函数定义代码。

    【旁白】 Python 定义函数用 def 关键字，格式是——def 函数名、参数、冒号、缩进的函数体：

    def build_messages(system_prompt, user_input):
    """构建 API 消息列表"""
    return [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_input}
    ]

    拆开看：def 是关键字，build_messages 是函数名，括号里是参数，冒号结尾，下面缩进的就是函数体。return 给出返回值——函数执行完"吐出来"的东西。

    调用：

    msgs = build_messages("你是翻译助手", "翻译：Hello")
print(msgs)

    函数名你喊一下，参数你填进去，结果你就拿到了。跟叫外卖一样——你说"一份番茄炒蛋"，厨房（函数）做好端出来（return）。

    [2:00-3:30] 参数设计：位置、关键字、默认值¶

    【画面】 继续敲入不同参数形式的代码。

    【旁白】 参数有三种用法，你至少要会前两种。

    位置参数——按顺序传，最基本：

    def extract_reply(response, prefix="AI: "):
    return prefix + response.choices[0].message.content

# 按位置传第一个，第二个用默认值
reply = extract_reply(response)

    关键字参数——按名字传，不依赖顺序：

    reply = extract_reply(response, prefix="回复: ")

    默认值参数——给参数一个默认值，不传就用默认的。上面 prefix="AI: " 就是默认值。

    现在看一个真实的组合——API 调用函数，有默认值：

    def chat(user_input, model="deepseek-chat"):
    messages = build_messages("你是助手", user_input)
    # 这里省略 API 调用细节
    return f"[{model}] 收到：{user_input}"

print(chat("你好"))                    # 用默认模型
print(chat("你好", model="deepseek-reasoner"))  # 指定模型

    不传 model 就用默认值 deepseek-chat，传了就用你指定的。这种"带默认值的参数"在 AI 开发里到处都是。

    [3:30-4:30] 函数契约四要素¶

    【画面】 PPT 动画：一个合同模板，四个空格依次填入——函数名、参数、返回值、示例。

    【旁白】 函数设计有一个核心思维叫"函数契约"。一份完整的契约包含四样东西：

    ① 函数名——要能自解释。build_messages 比 func1 好，build_messages 比 do_messages 好。名字就是文档。

    ② 参数——名称和类型。system_prompt(str) 比 x 好。

    ③ 返回值——返回什么类型？字符串？列表？字典？写清楚。

    ④ 示例——给一个调用例子。

    def count_tokens(response):
    """统计 API 调用的 token 用量

    参数:
        response: API 返回的响应对象
    返回:
        int: 总 token 数
    示例:
        >>> count_tokens(response)
        145
    """
    return response.usage.total_tokens

    这段文档字符串（docstring）就是契约。你可能会问——写这么详细有必要吗？答案是：好的函数契约就是好的 prompt。你把契约发给 AI，AI 就能帮你生成精确的函数体。下一集我们会演示这个技巧。

    [4:30-5:45] 可运行闭环：重构内联代码为函数¶

    【画面】 屏幕左右分屏——左边是重构前的面条代码（快速滚动），右边是重构后的三个函数。逐个函数高亮展示。

    【旁白】 来看今天的完整闭环——把开头那段 40 行面条代码重构为三个函数：

    def build_messages(system_prompt, user_input):
    """构建 API 消息列表"""
    return [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_input}
    ]


def extract_reply(response):
    """从 API 响应中提取回复文本"""
    return response.choices[0].message.content


def count_tokens(response):
    """统计本次调用的 token 用量"""
    return response.usage.total_tokens

    重构后的主逻辑变得极清晰：

    # --- 主逻辑（5 行）---
messages = build_messages("你是翻译助手", "翻译：Hello World")
# response = client.chat.completions.create(model="deepseek-chat", messages=messages)
# ↑ 录制时用模拟数据代替
mock_response = type("R", (), {
    "choices": [type("C", (), {"message": type("M", (), {"content": "你好，世界"})()})()],
    "usage": type("U", (), {"total_tokens": 45})()
})

print("回复：", extract_reply(mock_response))
print("Token用量：", count_tokens(mock_response))

    注意——这不是代码变少了，而是逻辑变清晰了。每个函数只做一件事，名字告诉你它在干什么。以后想改"提取回复"的逻辑，只改 extract_reply 一个函数，不用动别的。

    [5:45-7:00] 可变默认参数陷阱¶

    【画面】 屏幕上展示一段"看起来没问题"的代码，运行后结果出乎意料。红色标注关键行。

    【旁白】 最后讲一个坑——AI 最常生成的 bug 之一：可变默认参数陷阱。

    看这段代码：

    def add_message(history=[], message="hello"):
    history.append({"role": "user", "content": message})
    return history

print(add_message(message="第一条"))
print(add_message(message="第二条"))

    你觉得第二次调用输出什么？只有"第二条"对吧？

    运行——[{'role': 'user', 'content': '第一条'}, {'role': 'user', 'content': '第二条'}]。两条都在！

    为什么？因为 Python 的默认参数在**函数定义时只创建一次**，不是每次调用都新建。这个空列表 [] 被所有调用共享了。

    正确写法：

    def add_message(history=None, message="hello"):
    if history is None:
        history = []
    history.append({"role": "user", "content": message})
    return history

    用 None 做哨兵值，在函数体里检查并创建。记住——看到 =[] 或 ={} 做默认参数就要警觉，这是 AI 代码审查的高频考点。

    [7:00-7:50] 小结 + 引出下集¶

    【画面】 字幕条："def 函数名(参数): return · 函数契约 = 名字+参数+返回值+示例 · 警惕可变默认参数"

    【旁白】 今天三件事：def 定义函数、函数契约四要素让代码自文档化、可变默认参数陷阱要警惕。

    【画面】 提问彩蛋。字幕条依次列出三个可以直接照抄去问 Kimi/DeepSeek 的 prompt：

    • ① 扮演代码评审：我发你一段 20 行的平铺代码，请不要直接重写，而是先问我每个函数该叫什么、该返回什么，引导我自己完成拆分。
    • ② 用"可变默认参数陷阱"出 3 道预测输出题，比如 def f(history=[]) 连续调用两次会输出什么，我答完再讲解原理。
    • ③ 用 AI 开发里的真实例子，给我讲清楚位置参数、关键字参数、默认值参数的区别，以及什么时候必须用关键字传参。

    【旁白】 三个 prompt 直接照抄。再多说一句——让 AI 帮你写函数不难，难的是设计函数。所以让它反问你：这个函数该叫什么、该返回什么。设计是你想清楚的，代码才轮到它帮你写。

    【旁白】 下集我们讲两个你会在 AI 生成代码里到处看到的东西——*args 和 **kwargs，以及一行搞定的小函数 lambda。你不需要会写，但必须能看懂。

    完整演示代码¶

    # === V015 演示完整代码 ===

# --- Part 1: def 基本语法 ---
def build_messages(system_prompt, user_input):
    """构建 API 消息列表"""
    return [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_input}
    ]

msgs = build_messages("你是翻译助手", "翻译：Hello")
print(msgs)

# --- Part 2: 参数设计 ---
def chat(user_input, model="deepseek-chat"):
    messages = build_messages("你是助手", user_input)
    return f"[{model}] 收到：{user_input}"

print(chat("你好"))
print(chat("你好", model="deepseek-reasoner"))

# --- Part 3: 函数契约 ---
def count_tokens(response):
    """统计 API 调用的 token 用量

    参数:
        response: API 返回的响应对象
    返回:
        int: 总 token 数
    """
    return response.usage.total_tokens

# --- Part 4: 重构闭环 ---
def extract_reply(response):
    """从 API 响应中提取回复文本"""
    return response.choices[0].message.content

# 模拟 API 响应对象（录制时不需要真实 API）
class MockResponse:
    def __init__(self, content, tokens):
        self.choices = [type("C", (), {"message": type("M", (), {"content": content})()})()]
        self.usage = type("U", (), {"total_tokens": tokens})()

mock_response = MockResponse("你好，世界", 45)

# 主逻辑
messages = build_messages("你是翻译助手", "翻译：Hello World")
print("消息列表:", messages)
print("回复：", extract_reply(mock_response))
print("Token用量：", count_tokens(mock_response))

# --- Part 5: 可变默认参数陷阱 ---
def add_message_bad(history=[], message="hello"):
    history.append({"role": "user", "content": message})
    return history

print("--- 可变默认参数陷阱 ---")
print(add_message_bad(message="第一条"))
print(add_message_bad(message="第二条"))

# 正确写法
def add_message_good(history=None, message="hello"):
    if history is None:
        history = []
    history.append({"role": "user", "content": message})
    return history

print("--- 正确写法 ---")
print(add_message_good(message="第一条"))
print(add_message_good(message="第二条"))

    录制注意¶

    1. MockResponse 简化：视频中用 MockResponse 模拟 API 响应对象是为了录制时不依赖网络。但如果录制环境网络正常，可以直接用 from openai import OpenAI 做真实调用，更直观。两种方案都可行，录制前测试确保代码能跑通。
    2. 可变默认参数是高光时刻：Part 5 的运行结果一定要让观众看到"第二条"输出里包含"第一条"——这个反直觉的输出是本集最强记忆点。可以在输出那帧加一个放大或高亮效果。
    3. 字幕条重点：函数契约四要素出字幕条——"①函数名 ②参数 ③返回值 ④示例"。可变默认参数陷阱也出一条——"默认参数用 None，不用 [] 或 {}"。
    4. 时长控制点：如果 Part 3（函数契约 docstring 展示）讲慢了，可以把 Part 4 闭环中的 MockResponse 部分提前说明"这里用模拟数据代替真实 API"，跳过 class 定义细节直接看调用结果。
    5. 提问彩蛋字幕：提问彩蛋段的 prompt 字幕条需在后期加上，确保观众能暂停照抄。
