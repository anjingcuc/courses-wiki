    一句话定位 用"拍照"类比讲透 Git 三板斧（add→commit→push），用"平行宇宙"讲分支，学会"AI 大改之前先 commit"

    逐字稿¶

    [0:00-0:30] 开场 Hook¶

    【画面】屏幕录制：VSCode 中打开 chat.py，让 AI（Trae/Kimi Code）给代码加功能，AI 大改一通后运行报错，红色错误信息满屏。然后按 Ctrl+Z 很多下，画面手忙脚乱。字幕弹出："Ctrl+Z 按到手抽？"

    【旁白】你有没有遇到过这种情况——让 AI 帮你改代码，结果改出一堆 bug，想退回去？Ctrl+Z 按了几十下手都酸了，还不一定能退对。更惨的是，如果昨天改的今天才发现坏了呢？根本没法撤销。别慌，如果你用了 Git，一秒钟就能回到之前能跑的版本。今天我来教你 Git 的三板斧，让你从此告别"代码翻车无法回退"的噩梦。

    [0:30-3:00] Git 三板斧：拍照类比¶

    【画面】屏幕切到幻灯片：三张图标依次出现——相机取景框（标 git add）→ 快门按钮（标 git commit）→ 云上传图标（标 git push）。然后切回终端录屏，实际操作 git add → git commit → git push，每步后展示 git status 输出变化。

    【旁白】Git 的核心操作其实就三板斧，我用"拍照"来给你打个比方，特别好记。

    在讲之前，先理解一个概念——Git 管理的是"版本"。你每次改完代码，Git 帮你存一个快照。这样不管你改了多少次，随时都能翻回去。

    第一步，git add，就是你选好要入镜的东西。你改了哪个文件，就把它选进暂存区，就像你把人拉到镜头前面准备拍照。来看终端——我刚改了 chat.py，输入 git status，你会看到红色的 chat.py，红色表示这个文件被改过了但还没入镜。现在输入 git add chat.py，再敲一遍 git status，看到没？颜色变绿了，说明它已经准备好被拍了。记住，git status 是你最常用的命令，随时敲一下就知道仓库现在什么状态。

    第二步，git commit，就是按下快门拍一张照片。这句话特别重要——commit 是保存在你自己电脑上的，就算断网也能 commit，不需要联网。你每 commit 一次就拍了一张"版本快照"，以后随时能回到这个状态。来看，输入 git commit -m "L4作业：第一次API调用"，回车。看到没有？它告诉你创建了几个 commit，改了几个文件。这里引号里的话叫 commit message，就是你给这张照片取的名字。千万别写"update"或者"改了点东西"这种废话，一定要写清楚到底改了什么。不然以后翻相册的时候，面对一堆叫"update"的照片，你自己都不知道哪张是哪张。

    第三步，git push，就是把这照片上传到云端相册。记住，commit 只保存在你自己电脑上，push 之后代码才同步到远程服务器——老师才能在 GitLab 上看到你的作业。如果不 push，那别人是完全看不到你的代码的。来看终端，输入 git push origin 0x00，等几秒，上传成功。

    三步连起来就是一句话：add 选入镜，commit 按快门，push 传云端。你把这个顺序记住，日常使用 Git 基本就没问题了。

    [3:00-4:30] 分支：平行宇宙¶

    【画面】幻灯片动画：一条主线（main）向右延伸，中间分叉出一条支线（0x00），支线上有一串操作节点。切到终端，演示 git checkout -b 0x00，然后在分支里改代码，再 git checkout main 切回，用 cat chat.py 展示代码回到原样。字幕："分支 = 平行宇宙"。

    【旁白】三板斧学会了，接下来讲一个更厉害的概念——分支。

    分支是什么？你可以把它理解为"平行宇宙"。你的 main 分支就是主线剧情，代码一直在那儿好好的，是稳定能跑的版本。你现在创建一个新分支，就是在主线旁边开了一个平行宇宙。在这个平行宇宙里面你可以随便折腾，改代码、加功能、搞实验，怎么玩都不影响主线。这就是它最妙的地方。

    来看终端，输入 git checkout -b 0x00，这一条命令做两件事：创建一个叫 0x00 的新分支，并且切换过去。我们这门课的规范是每次作业一个分支，命名就用 0x00、0x01 这样往上加。在分支里我改一下代码，commit 之后，输入 git checkout main 切回主线。你看，代码瞬间回到原来的样子，刚才在分支里改的东西全都不见了。

    是不是很像平行宇宙？你在支线里翻天覆地，主线纹丝不动。等你在分支里把作业做完了、测试没问题了，再把它合并回主线。这就是分支的威力——它让你可以放心做实验，不怕搞坏原版。

    另外两个常用命令也提一下：git status 查看当前状态——改了什么、在哪个分支；git log --oneline 查看提交历史——你拍过的每一张"照片"都在，一行一行列出来。

    [4:30-6:00] .gitignore：保护你的 API Key¶

    【画面】终端录屏：先展示一个没有 .gitignore 的场景，git status 中出现了红色的 .env 文件，旁边打一个红色警告标记。然后创建 .gitignore 文件，写入内容后保存，再次 git status，.env 消失。字幕弹出核心原则："Key 放 .env，.env 入 .gitignore"。

    【旁白】讲完了三板斧和分支，有一个东西我必须单独拿出来说——.gitignore。上节课你写的 chat.py 里面有什么？有你的 API Key。如果直接把 Key push 到 GitLab 上，全班同学都能看到，你的 Key 分分钟被别人拿去刷，钱包可能就被掏空了。

    怎么保护？用 .gitignore 文件。这个文件的作用就是告诉 Git："这里面的文件你统统不要管，不要 add，不要 commit，不要 push。"

    来看怎么配。在项目根目录创建一个 .gitignore 文件，写入这几行：.env、__pycache__/、*.pyc、.vscode/。什么意思呢？.env 是你的密钥文件，绝不提交；__pycache__/ 和 *.pyc 是 Python 运行时自动生成的缓存，没必要提交；.vscode/ 是编辑器配置，每个人环境不同，也不提交。

    配好之后，再 git status，你看，.env 文件从列表里消失了，Git 完全忽略它，就好像它不存在一样。你的 Key 就安全了。

    记住一个原则：Key 放在 .env 文件里，.env 写进 .gitignore。代码里不硬编码 Key，让别人看你的代码也看不出 Key 是什么。这一条比任何技巧都重要——Git 的历史记录是删不掉的，一旦提交了就追不回来，所以预防比补救重要一百倍。

    [6:00-7:00] 完整作业流程 + 回退演示¶

    【画面】终端录屏，快速回放完整流程。然后演示"AI 改坏了怎么办"——git checkout chat.py 丢弃修改，文件秒回原样。最后画面定格在核心口诀字幕上。

    【旁白】好，我们把完整流程从头到尾串一遍。第一步 git clone，把课程仓库克隆到本地。第二步 git checkout -b 0x00，创建作业分支。第三步把 chat.py 放进来，配上 .gitignore 保护 Key。然后 git add、git commit、git push 三连。六步走完，代码就稳稳躺在 GitLab 上了。这就是你以后每次交作业的标准流程。

    再演示一个救命操作。假设你让 AI 改了 chat.py，改完运行报错了，想退回去怎么办？一行命令：git checkout chat.py，回车，文件秒回上次 commit 的状态，AI 的修改全部丢弃。这就是为什么我一直说——AI 大改之前先 commit。先存住能跑的版本，改坏了一秒回退，你可以大胆让 AI 去试。

    给大家一句口诀："AI 大改之前先 commit，提交之前先看 .gitignore。"

    [7:00-8:25] 小结、提问彩蛋与引出下集¶

    【画面】幻灯片回顾：三张图标（add→commit→push）+ 分支图示 + .gitignore 标志 + 核心口诀。

    【旁白】最后回顾一下今天学的。Git 三板斧：add 选入镜，commit 按快门，push 传云端。分支就是平行宇宙，让你放心做实验不怕搞坏主线。.gitignore 保护你的 API Key，敏感文件绝不提交。最重要的是那句口诀：AI 大改之前先 commit，提交之前先看 .gitignore。

    到这里，M1 环境与工具链模块全部结束。回顾一下你已经拥有的能力：Python 运行环境、VSCode 编辑器、AI 编程工具、大模型 API 调用、以及今天学的版本控制。这五样东西就是你的全套装备。

    【画面】字幕条逐条弹出三个可直接照抄的 prompt（每条停留供暂停截图）： ① 我在学 Git。出 3 个场景题考我，比如"AI 把代码改坏了想回到上个版本""改了一半不想提交"，问我该用哪条命令，我回答后你再讲评。 ② 不用"拍照"的类比，换一种方式给我讲清 git add、commit、push 的区别，讲完出一道判断题检验我。 ③ 扮演严格的项目经理，检查我的 .gitignore 配置（我粘贴给你），指出漏掉了哪些不该提交的文件，并说明后果。

    【旁白】最后留个提问彩蛋。Git 命令不难背，难的是知道什么场景用哪条。让 AI 给你出场景题——答错一次，比背十遍命令表都管用。这三条 prompt 暂停照抄，让 AI 当一回你的考官。

    【画面】最后弹出模块地图：M1 环境与工具链（Python / VSCode / AI 工具 / API 调用 / Git 全部打勾），箭头指向 M2 语言核心。

    【旁白】下节课我们进入 M2 语言核心。而且我要告诉你一个好消息——从下集开始，我们操作的数据全部是大模型 API 返回的真实 JSON。学语法的同时，你就在学 AI 开发。下集见。

    演示操作清单¶

    完整命令序列（按录制顺序）¶

    # ===== 1. Git 三板斧演示 =====

# 查看当前状态（改了哪些文件）
git status

# 将修改的文件加入暂存区（选入镜）
git add chat.py

# 再次查看状态（确认已暂存）
git status

# 提交到本地仓库（按快门）
git commit -m "L4作业：第一次大模型API调用"

# 推送到远程仓库（传云端）
git push origin 0x00

# ===== 2. 分支演示 =====

# 创建并切换到新分支（开平行宇宙）
git checkout -b 0x00

# 查看提交历史
git log --oneline

# 查看当前所在分支
git branch

# 切换回 main 分支（回到主线）
git checkout main

# ===== 3. .gitignore 演示 =====

# 不配 .gitignore 时，git status 会显示 .env
git status

# 创建 .gitignore（见下方文件内容）
# 配好后再看，.env 从列表中消失
git status

# ===== 4. 完整作业提交流程 =====

# 克隆课程仓库
git clone https://gitlab.example.com/python-2026/你的学号.git
cd 你的学号

# 创建作业分支
git checkout -b 0x00

# 查看状态
git status

# 添加文件
git add chat.py
git add .gitignore

# 提交
git commit -m "L4作业：第一次大模型API调用"

# 推送
git push origin 0x00

# 查看历史
git log --oneline

# ===== 5. 回退演示（AI 改坏了代码时）=====

# 丢弃单个文件的修改，回到上次 commit 的状态
git checkout chat.py

    .gitignore 文件内容¶

    # .gitignore — 不提交到 Git 的文件
.env
__pycache__/
*.pyc
.vscode/

    项目文件结构（作业提交规范）¶

    你的学号/
├── .gitignore          # 排除规则（提交）
├── .env                # API Key 存放（不提交，被 .gitignore 排除）
├── .env.example        # 配置模板（提交，告诉别人需要什么 Key）
├── chat.py             # 主代码（提交）
└── README.md           # 说明文档（提交）

    录制注意¶

    1. 终端字号要大：所有 Git 命令和输出在录屏中必须清晰可读，建议 18px 以上。git status 的颜色变化（红→绿）是关键教学信号，确保录屏不偏色。
    2. 三板斧演示要慢：add 之后停一下展示 status 变化，commit 之后停一下展示输出信息，push 之后停一下展示成功提示。不要一口气敲完三行命令，学生需要看到每一步的效果。
    3. 分支切换要对比：在分支里改了代码后，切回 main 时用 cat chat.py 或直接打开文件展示"代码回到原样"，让观众直观感受"平行宇宙"的效果。对比越鲜明，概念越清楚。
    4. .gitignore 演示用对比法：先不加 .gitignore 就 git status，让观众看到 .env 出现在列表里（危险）；然后加上 .gitignore 再看一次，.env 消失（安全）。这种"犯错→修正"的演示比直接展示正确流程更有记忆点。
    5. 回退演示要真实：实际在编辑器里改坏 chat.py（比如删几行或加几行乱码），保存后运行报错，再用 git checkout chat.py 恢复。展示"一秒回退"的爽感。
    6. 口诀要重复：核心口诀"AI 大改之前先 commit，提交之前先看 .gitignore"在正文中出现两次（正文 + 小结），录制时语速放慢、加重语气，确保观众记住。
    7. 提问彩蛋：提问彩蛋段的 prompt 字幕条需在后期加上，确保观众能暂停照抄。
