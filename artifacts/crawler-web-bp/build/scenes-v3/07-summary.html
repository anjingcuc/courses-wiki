拿到一个 URL 先做什么？

← 点左边任一分支，展开它的「代价 / 代码骨架 / 坑」

代价
最低。一次 requests.get 拿到结构化数据，不渲染、不解析 DOM；前置成本只是「找到接口」。
骨架 
api = "https://site.com/api/comments?page=1"
r = requests.get(api, headers=HDR, timeout=10)
items = r.json()["data"]["list"]
坑
接口常校验 Referer / Cookie / 签名；响应可能是 JSONP，先剥回调壳；分页参数顺着 Network 里的请求一个个翻。
代价
低。整页 HTML 已经就绪，写选择器即可；页面改版时选择器要跟着改，这是主要维护成本。
骨架 
import requests
from bs4 import BeautifulSoup

r = requests.get(url)
r.encoding = "utf-8"                       # 不指定编码，中文会乱码
soup = BeautifulSoup(r.text, "html.parser")
for li in soup.select("li"):               # li 选出来是一整个 list
    print(li.text)                         # .text 只要元素里的文本
坑
不写 r.encoding = "utf-8" 中文就乱码；<a href> 是相对链接，要拼上前缀才是完整 URL；select 返回 list，要逐个 .text 取文本。
代价
最高。启浏览器、占内存、每页数秒；部署还要装 driver 与浏览器，能不用就不用。
骨架 
driver.get(url)
WebDriverWait(driver, 10).until(
    EC.presence_of_element_located((By.CSS_SELECTOR, ".comment-item")))
html = driver.page_source
坑
用显式等待，别用 time.sleep；等 networkidle 或滚动触发懒加载；关图片、禁视频能明显提速。

01

【案例 A】抓静态学生名单，最后对账发现首页被抓了两次。最先该改哪一处？

答案 Bindex.html 和「1」指向同一页，但字符串不同 —— 字典按字符串比对，判重就失效了。先去锚点、去尾斜杠，再拿归一化后的结果当 key。

02

【案例 B】首屏只有 20 条，Network 里滚出一条 data?page=2 且返回 JSON。最优做法是？

答案 B接口已经暴露在 Network 里、又不用鉴权，每页一次请求就拿完；headless 能拿到，但要等渲染，留作接口抓不到时的兜底。

03

【案例 C · 来自 Web 开发课】库存 1000→999，页面没跳、Doc 只请求了 1 次。这说明发生了什么？

答案 B整页只请求 1 次、页面没跳，却只有那个数字变了 —— 数字来自 XHR 响应。只要这一个数，就优先打接口，别去解析 DOM。
