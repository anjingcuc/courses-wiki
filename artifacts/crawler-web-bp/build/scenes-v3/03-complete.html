只要响应里有完整 HTML，静态站和后端动态都能直接抓

静态站是「把磁盘上的文件发给你」，后端动态是「现场把模板拼一份再发给你」—— 产出路径不同，到客户端手里的东西是同一种：一整页已经填好数据的 HTML。 所以「后端动态」不等于「必须上无头浏览器」；判据只有一条，看响应体。

①静态站实战 · 127.0.0.1:8000

import requests
from bs4 import BeautifulSoup
url = "http://127.0.0.1:8000" # python -m http.server 8000
r = requests.get(url) # 浏览器发的也是这个 GET
r.encoding = "utf-8" # 不设 → 标题里的中文乱码
soup = BeautifulSoup(r.text, "html.parser")
li_list = soup.select("li") # 返回 list（示意：30 个）
for li in li_list:
print(li.text) # 只要文本，不要标签

讲师现场从零重写的就是这十行：先确认 r.text 「是一个完整的页面，跟我们用浏览器看到这个页面是一致的」，再去浏览器里右键检查元素， 发现「所有学生的名字的 ID 都存在 li 这个元素里面」，于是选择器写 li。

后端动态真正改变的只有「变量填什么」，响应仍然是完整 HTML。 对爬虫来说，这类页面就是「参数化的静态页」：遍历 username 与 page 就够，不用开浏览器。

③讲师自己踩的坑 · 首页被抓了两次

讲师自己的爬虫把首页抓了两次：首页是 index.html，而页面里「1」那个链接又指向 index.html —— 字符串不同 → 判重失效 → 重复抓取。 字典的 key 唯一没错，错在 key 没先归一化：相对路径、结尾斜杠、默认页、#fragment 都会让同一个页面变成两个字符串。

from urllib.parse import urljoin, urldefrag
def norm(base, href):
u = urldefrag(urljoin(base, href))[0] # 补绝对路径 + 去掉 #fragment
path, _, qs = u.partition("?")
path = path.rstrip("/") or "/" # 结尾斜杠去掉（根除外）
return path + ("?" + qs if qs else "")
seen = {norm(base, "/"): False} # key 先归一化，字典才真的能去重

④为什么「后端动态」不等于「必须无头」

一个页面什么时候才需要无头浏览器，只看一件事：响应体里有没有内容。

  • 有完整 HTML → requests + 选择器就够（静态站、后端渲染的站都属这类）
  • 只有空壳 + 页面自己也在要数据 → 先按 F12 找 XHR；有可用接口就直接取 JSON
  • 接口也拿不到，或必须完整执行页面 → 再轮到 Selenium / Playwright（headless 为教学扩展）
判断动作只有一步：Ctrl+U 看源码，或者 curl 一下看响应体。 源码里就有学生名单 → 这站对爬虫是「静态」的，哪怕它是 Flask 现场生成的。

⑤服务器侧怎么把请求交给 Python · 不影响你看到什么，但影响开销、整合度与灵活性Web 开发 · 第十一节 P2

CGI 一个请求起一个进程 跑完就退出，下次再来再起。讲师原话：进程起太多「切换不过来了，它挂了」—— 就是常说的 web 服务器被 DoS
FastCGI 常驻进程 + IPC 复用 逻辑不变，只是把「不断起新进程」这一步干掉了，请求靠进程间通信送进去
WSGI Python 侧的调用约定 server → 中间件（多给一个 callback）→ 应用函数；小作业里 Flask 自带 HTTP 与 WSGI，不必装 Apache / Nginx 这类独立服务器

这三种是「服务器怎么把请求交给 Python 程序」的管道差异：客户端拿到的仍是一整串 HTML，所以静态抓取照样有效；对工程而言它决定的是开销、整合度与部署灵活性 —— 能不能换掉 web server、能不能在中间件里加日志与鉴权，都在这一层。以上 CGI / FastCGI / WSGI 三段出自 Web 开发课，非爬虫课原话

本屏结论

后端动态 ≠ 必须无头。响应体里有完整 HTML，就能 requests + BeautifulSoup 直接抓； 真正需要浏览器的是「内容由 JS 在客户端画出来」的那种页面。
