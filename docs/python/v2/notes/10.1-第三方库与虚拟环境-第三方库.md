# 10.1 第三方库与虚拟环境——第三方库

## 内容梗概

本节是"第三方库与虚拟环境"章节的开场课。老师先衔接上节课"模块与包"的知识，引出第三方库的概念——其他开发者写好、可通过网络安装到本机后直接 `import` 使用的包；同时预告了虚拟环境的动机（一台机器上存在多个 Python 环境/版本时需要管理）。随后以 `requests` 库为例演示了 `ModuleNotFoundError` 报错及用 `pip install` 安装第三方库的基本流程，并强调了"不要重复造轮子"的开发思路。

## 知识点详解

### 1. 本章内容框架（约 00:00–02:19）
- 承接上节课：Python 的模块和包放在文件系统的特定路径下，"一个文件对应一个模块，一个文件夹就是一个包"，可以自己在文件系统中找到它们。
- 本章包含两部分内容：**第三方库** 和 **虚拟环境**。
- 虚拟环境的动机：默认情况下所有包都装在 Python 安装目录下；但一台电脑上常有多个 Python 环境（如人工智能课的 Anaconda 环境、本课程单独的 Python 环境、其他环境），需要管理。

### 2. 什么是第三方库（约 02:19–03:40）
- 第三方库本质上就是**别的开发者写好的包**，通过网络安装到自己的机器上后，`import` 进来即可使用。
- 第三方库是 Python 最大的特点/优势之一，各种各样的库都有。

### 3. 不要重复造轮子（约 03:40–04:54）
- 常规思路：想实现一个功能时，先想这个功能是不是大家都要用、别的开发者是否也遇到过同样问题；**务必在手动造轮子之前先上网搜有没有现成的成熟包**，以提升开发效率。
- 例外：如果目的是锻炼编程能力，从头自己写完全没有问题。

### 4. requests 库示例与 pip install（约 04:54–06:37）
- `requests`：非常有名的、以 HTTP 协议与 Web 服务器通信的库，说大白话就是"用来爬网页的库"（课程概述的爬虫示例就用到了它）。
- 使用前先 `import requests`；未安装时会报 `No module named 'requests'` 错误——老师再次强调**一定要读报错信息**。
- 安装方法（命令行中）：`pip install requests`。
- 按 `Ctrl+C` 可以中断安装过程。

## 示例与演示

- 在干净的 Python 环境中 `import requests`，复现 `No module named 'requests'`（即 `ModuleNotFoundError`）报错；然后在命令行执行 `pip install requests` 完成安装，再次 `import` 即不再报错。
- 提及课程概述课（第 1 章）给出的爬虫等示例：课后自己重现这些示例时，会遇到"找不到某个模块"的报错，解决办法就是按示例要求安装对应的第三方库。

## 重点与难点

- **读报错**：`No module named 'xxx'` 说明缺少对应模块，装库即可，这是新手最常遇到的问题。
- **先搜现成的包再动手写**：这是工程实践中的重要习惯，能显著提升开发效率。
- 区分概念：第三方库 = 别人写好的包；虚拟环境解决的是"多版本/多环境"的管理问题（本节只点到为止，后续展开）。
