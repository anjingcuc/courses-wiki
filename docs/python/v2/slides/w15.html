前端联调：三大坑速查

① CORS 后端加 CORSMiddleware(allow_origins=[前端地址])——是配置机制，不是绕开。
② 字段名不匹配 后端返 reply 前端读 answer → undefined。排查口诀：对着接口文档逐字核对。
③ 流式渲染 后端 StreamingResponse + 前端 fetch + getReader() 逐块读——打字机效果的技术内核。

UX 三要素顺手补齐：加载状态（点了要有反馈）、错误提示（别白屏）、空状态（「还没有对话，开始聊吧」）。

AI-free 调试日：规则宣布

从现在起关闭所有 AI 工具。只允许用 print / 日志 / 断点 / 读报错，修自己项目里的 bug。

为什么？——建立「没有 AI 时我能做什么」的能力底座。工具越强，越要知道自己值多少。

课后解禁的学习姿势：把今天卡住的问题拿去问 AI——不是让它修，而是让它 讲透原理、出变式题自测。调试经历转化为问题，才是把 AI 用成老师。

没有 AI 时的四件武器

武器一读报错 Traceback 从最后一行往前读——最后一行是错误类型，往上找到你自己代码的那一帧。
武器二print 二分 怀疑哪段就打哪段——在中间打一个 print，值不对就再对半排查。
武器三断点调试 VSCode 行号左侧点一下 → F5 → 单步走，亲眼看变量变化。
武器四最小复现 把 bug 剥到最小可运行示例——往往剥着剥着自己就看出来了。

课堂节奏：先按「边界场景清单」折腾自己的应用（空输入/超长文本/特殊字符/断网），把 bug 逼出来记清单，再逐个修。

  • 提 Bug 的规范：复现步骤 + 预期行为 + 实际行为——不是一句「这个坏了」
  • 别人帮你测出 bug 是帮助，不是挑刺——测试是团队协作的语言

部署就绪：让别人也能跑

my_project/
├── .env.example        # 密钥模板：DEEPSEEK_KEY=（留空）
├── requirements.txt   # pip freeze 导出的精确清单
├── README.md          # 从 clone 到看到界面的每一步
└── app/ ...
  • 「我电脑上能跑」≠ 别人能跑：环境变量模板化 + 依赖锁定 + 启动步骤是三件硬指标
  • 验收标准：找一个没接触过你项目的同学，只看 README 从零跑起来
  • 云部署是加分项——本地完整运行演示是底线（微课 V054 部署概念）
