    [0:00-0:35] 开场 Hook：等8秒 vs 0.5秒第一个字¶

    【画面】 分屏对比。左半屏：执行非流式调用，终端光标闪烁等待，画面右下角计时器从 0 跳到 8 秒，然后一次性打印出整段回复。右半屏：执行流式调用，0.5 秒第一个字就出现，文字逐字涌出。字幕条："等 8 秒看全部 vs 0.5 秒看第一个字"。

    【旁白】 看这个对比。左边——我发了条请求，光标闪了 8 秒，然后啪，一整段文字砸过来。右边——0.5 秒第一个字就出现了，文字像打字机一样逐个蹦出来。两段回复内容一样，但体验天差地别。左边让你焦虑，右边让你觉得"AI 在认真回应我"。右边这个效果叫流式输出，上集学完了参数旋钮，这集搞定流式——七分钟，让你的 AI 应用从"能跑"变成"好用"。

    [0:35-1:30] 为什么需要流式¶

    【画面】 PPT 动画：左侧画一个水龙头，一次性倒满一大桶水，等了很久；右侧画一个水龙头，水一点一点流进杯子。字幕："非流式 = 一次倒满 · 流式 = 持续流出"。

    【旁白】 先说清楚为什么需要流式。大模型生成文本不是瞬间的——它是逐个 token 往外吐的，就像水龙头出水。非流式模式下，API 会等 AI 把整段话全部生成完，再一次性打包返回给你。中间这几秒甚至十几秒，你的程序只能干等，用户只能看一个加载动画。

    流式模式就不一样了——AI 每生成一小段，API 就立刻推送给你，你拿到一段就显示一段。用户不需要等 AI 想完所有内容，0.5 秒就能看到第一个字。ChatGPT、DeepSeek 网页版那种打字机效果，底层就是这个机制。

    适用场景？几乎所有需要跟用户交互的 AI 应用——聊天机器人、AI 写作助手、代码助手。只要用户在看屏幕等回复，流式都是更好的选择。

    [1:30-3:15] stream=True：流式调用的基本写法¶

    【画面】 VS Code 中展示 demo_stream.py 代码，逐段讲解。先展示非流式调用（回顾），再加上 stream=True 参数。运行后展示逐字输出效果。

    【旁白】 怎么开启流式？其实就加一个参数——stream=True。来看代码。

    先回顾非流式，这是你一直在写的写法：

    response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "用100字介绍Python的历史"}]
)
print(response.choices[0].message.content)

    response 是一个完整的响应对象，.choices[0].message.content 一次拿到全部文本。

    现在加流式——只改一个地方：

    stream = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "用100字介绍Python的历史"}],
    stream=True
)

    加了 stream=True，返回的就不再是一个完整对象了，而是一个迭代器。你不能再用 .choices[0].message.content 去取，因为内容还没来齐。你需要用 for 循环，一块一块地接：

    full_text = ""
for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="", flush=True)
        full_text += delta

    来逐行拆解。for chunk in stream——每次循环拿到一个小数据块，叫 chunk。每个 chunk 里有一小段文字，通常就一两个字。chunk.choices[0].delta.content——注意这里和之前的区别，非流式是 .message.content，流式是 .delta.content。delta 就是"增量"，这一块新增加的文字。

    if delta 是因为有些 chunk 的 delta 是 None——比如第一个 chunk 只有角色信息没有内容，最后一个 chunk 标记结束也没有内容。判断一下，有内容才处理。

    [3:15-4:15] 最常见的坑：end="" 和 flush=True¶

    【画面】 代码放大，聚焦到 print(delta, end="", flush=True) 这一行。分两个动画拆解：先展示不加 end="" 时每个字后面都换行的混乱画面；再展示不加 flush=True 时光标一直闪、最后一次性全出来的画面。

    【旁白】 这行代码是流式输出里最容易踩的坑，单独说一下：

    print(delta, end="", flush=True)

    两个参数，一个都不能少。

    第一个 end=""——print 默认每次输出完会加一个换行符。但流式输出你要的是文字连续拼接，不能每个字都换行。end="" 就是告诉 print："输出完别加换行，让下一个字紧跟着。"

    第二个 flush=True——这是更隐蔽的坑。Python 的 print 默认有缓冲区，输出不会立刻显示到终端，而是攒一批再刷出来。结果就是——你以为会看到逐字效果，实际上光标闪了半天，最后一下子全出来了，和非流式没区别。flush=True 的意思就是"立刻刷新缓冲区，马上给我显示"。

    记住：流式输出，print 一定带 end="" 和 flush=True，两个都不能省。 这个坑踩过一次你就记住了。

    最后这行 full_text += delta——把每次拿到的碎片拼接起来，循环结束后 full_text 就是完整的回复文本。流式输出虽然逐字显示，但你仍然需要完整文本做后续处理，比如存到数据库、做 JSON 解析。

    [4:15-6:00] 可运行闭环：完整流式脚本¶

    【画面】 VS Code 中展示完整的 demo_stream.py，包含非流式对比和流式输出。运行脚本，先展示非流式的等待效果，再展示流式的逐字效果。终端左侧计时器辅助展示时间差。

    【旁白】 来看一个完整的可运行闭环，把非流式和流式放在一起对比：

    # demo_stream.py
import os
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

client = OpenAI(
    api_key=os.environ.get("DEEPSEEK_API_KEY", ""),
    base_url="https://api.deepseek.com"
)

prompt = "用 100 字介绍一下 Python 的历史"

# ---- 非流式：等全部生成完才返回 ----
print("【非流式】等待中...")
response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": prompt}]
)
print(response.choices[0].message.content)
print()

# ---- 流式：逐块返回，实时输出 ----
print("【流式】")
print("-" * 40)
stream = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": prompt}],
    stream=True
)

full_text = ""
for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="", flush=True)
        full_text += delta

print()
print("-" * 40)
print(f"完整文本长度: {len(full_text)} 字符")

    运行看效果。先是非流式——"等待中"，光标闪了几秒，然后整段文字一次出现。然后是流式——几乎立刻，第一个字就蹦出来了，文字逐个出现。最后 full_text 的长度也打印出来了，确认完整文本已经拼接好。

    这段代码你直接拿去就能跑。修改 prompt 换成任何问题，流式效果立刻生效。

    [6:00-6:45] 封装 llm_chat() 函数¶

    【画面】 VS Code 中展示 llm_utils.py 文件，聚焦到 llm_chat() 函数签名和流式分支。高亮 stream: bool = False 参数和 if stream: 分支逻辑。

    【旁白】 最后一步——把流式封装进一个可配置的函数。上节课我们一直在写零散的调用代码，现在该收拢了。封装一个 llm_chat() 函数，支持非流式和流式两种模式：

    def llm_chat(
    user_message: str,
    system_prompt: str = "你是一个有帮助的AI助手。",
    model: str = "deepseek-chat",
    temperature: float = 0.7,
    max_tokens: Optional[int] = None,
    stream: bool = False
) -> str:
    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_message}
    ]

    kwargs = {
        "model": model,
        "messages": messages,
        "temperature": temperature,
    }
    if max_tokens is not None:
        kwargs["max_tokens"] = max_tokens

    if stream:
        response = client.chat.completions.create(stream=True, **kwargs)
        full_text = ""
        for chunk in response:
            delta = chunk.choices[0].delta.content
            if delta:
                print(delta, end="", flush=True)
                full_text += delta
        print()
        return full_text
    else:
        response = client.chat.completions.create(**kwargs)
        return response.choices[0].message.content

    核心就是 stream 参数。默认 False，走非流式分支，直接返回完整文本；传 True，走流式分支，逐字打印同时拼接完整文本，最后返回。两种模式返回的都是 str，调用方式完全一样：

    # 非流式
reply = llm_chat("Python 是什么？")

# 流式
reply = llm_chat("Python 是什么？", stream=True)

    这个函数是你后续所有 AI 应用的基础设施——下节课用它测 prompt，后面做 RAG、做 Agent 都会 import 它。存成 llm_utils.py，一劳永逸。

    演示2：可配置的 llm_chat() 函数（llm_utils.py）¶

    # llm_utils.py —— M5 全模块通用基础设施
"""可配置的大模型调用函数——L19 到 L30 的公共工具"""
import os
from openai import OpenAI
from dotenv import load_dotenv
from typing import Optional, List, Dict

load_dotenv()

# 模块级别创建一次 client（不要每次调用都创建）
_client = OpenAI(
    api_key=os.environ.get("DEEPSEEK_API_KEY", ""),
    base_url="https://api.deepseek.com"
)


def llm_chat(
    user_message: str,
    system_prompt: str = "你是一个有帮助的AI助手。",
    model: str = "deepseek-chat",
    temperature: float = 0.7,
    max_tokens: Optional[int] = None,
    history: Optional[List[Dict]] = None,
    stream: bool = False
) -> str:
    """调用大模型，返回回复文本

    参数:
        user_message: 用户消息内容
        system_prompt: 系统提示词，设定 AI 角色
        model: 模型名称（deepseek-chat / deepseek-reasoner 等）
        temperature: 温度，0=确定，1=随机，默认 0.7
        max_tokens: 最大输出 token 数，None 表示不限制
        history: 对话历史（消息列表），None 表示单轮对话
        stream: 是否流式输出

    返回:
        str: AI 回复的完整文本
    """
    # 构造消息列表
    if history:
        messages = history + [{"role": "user", "content": user_message}]
    else:
        messages = [
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_message}
        ]

    # 构造请求参数
    kwargs = {
        "model": model,
        "messages": messages,
        "temperature": temperature,
    }
    if max_tokens is not None:
        kwargs["max_tokens"] = max_tokens

    # 流式 vs 非流式
    if stream:
        response = _client.chat.completions.create(stream=True, **kwargs)
        full_text = ""
        for chunk in response:
            delta = chunk.choices[0].delta.content
            if delta:
                print(delta, end="", flush=True)
                full_text += delta
        print()  # 换行
        return full_text
    else:
        response = _client.chat.completions.create(**kwargs)
        return response.choices[0].message.content


# ---- 使用示例 ----
if __name__ == "__main__":
    # 示例1：基本调用（默认参数）
    print("=== 示例1：默认参数 ===")
    reply = llm_chat("Python 的 GIL 是什么？用一句话回答")
    print(reply)

    # 示例2：低温度（准确/代码场景）
    print("\n=== 示例2：低温度（temperature=0）===")
    reply = llm_chat(
        "写一个 Python 函数计算斐波那契数列第 n 项",
        temperature=0.0
    )
    print(reply)

    # 示例3：流式输出
    print("\n=== 示例3：流式输出 ===")
    reply = llm_chat("用 50 字描述编程的乐趣", stream=True)

    录制注意¶

    1. 开场对比必须有真实时间差：开场分屏对比是非流式 vs 流式的第一印象，必须真实运行。非流式部分保留完整等待时间（让观众感受到等待焦虑），流式部分重点展示第一个字快速出现的效果。可以在终端角落加计时器辅助展示。如果 API 返回太快（小于 3 秒），换一个稍长的 prompt（如"用 200 字介绍"）拉大时间差。
    2. flush=True 的坑要反面演示：讲解 flush=True 时，最好先展示不加它的效果——光标闪烁很久后一次性输出，和非流式没区别。然后再加上 flush=True，展示逐字效果。反面教材比正面讲解更有记忆点。
    3. llm_chat() 展示聚焦流式分支：函数完整代码较长，视频里不需要逐行念。聚焦展示两个要点：stream 参数控制模式切换、流式分支的 for 循环结构。完整代码放演示清单，学生课后自行阅读。

    5. 提问彩蛋字幕后期添加：提问彩蛋段的 prompt 字幕条需在后期加上，确保观众能暂停照抄。
