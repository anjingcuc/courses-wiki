**【画面】** 屏幕左侧是一段 AI 刚生成的 Python 代码，旁边弹出一个终端报错——`KeyError: 'data'`。画面一转，右侧是审查修正后的代码，终端输出"完成，共 12 条"。字幕条："AI 写的代码，你敢直接上线吗？"

**【旁白】** 你让 AI 写了一段代码，复制粘贴，一运行——竟然能跑。你松了口气，直接用。然后某天 API 返回了一个空列表，程序崩了。某天数据里混进来一个 None，又崩了。AI 写的代码跑是能跑，但你敢直接上线吗？今天教你用一份审查清单，找出 AI 代码里最常见的五类问题。八分钟，让你从"复制粘贴"进化到"审查后再生"。

### [0:30-1:15] 核心认知：初稿不是终稿

**【画面】** PPT 展示一张对比图——左边写"AI 代码 = 初稿"，右边写"你的代码 = 终稿"，中间一个箭头标着"审查 + 修改"。下方列出 AI 的思维方式："回答能实现功能的最短路径"。

**【旁白】** 先建立一个核心认知——**AI 生成的代码是初稿，不是终稿**。

为什么？因为 AI 回答问题时，它追求的是"能实现功能的最短路径"。你问它"写一个函数筛选分数大于 50 的记录"，它给你一个能跑的版本——但它不关心：变量名是否清晰、空值有没有处理、异常有没有捕获、代码将来好不好维护。这些是你的职责。

你把 AI 代码当代稿，审查一遍再使用——这叫"审查后再生"。接下来看五类最常见的问题。

### [1:15-2:15] 问题一：命名不一致 & 问题二：超纲语法

**【画面】** VS Code 中打开 `bad_code.py`，高亮第一段代码。先用红框标出变量名 `d`、`r`、`i`、`s`、`n`，再在另一段代码中圈出 `@dataclass` 装饰器。

**【旁白】** **第一类问题——命名不一致**。看这段代码：

```python
def processData(url, key):
    r = requests.get(url, headers={"Authorization": f"Bearer {key}"})
    d = json.loads(r.text)
    output = []
    for i in d.get("data", []):
        s = i.get("score")
        if s is not None and s > 50:
            output.append({"n": i["name"], "s": s})
    return output
```

`r` 是什么？`d` 是什么？`i`、`s`、`n` 又是什么？过两个月你自己回头看，都得从头读一遍。命名不一致是 AI 代码的"头号招牌"——同一个概念，这个函数里叫 `data`，换个函数又叫 `result`、又叫 `output`。审查时第一步就是统一命名，做到见名知意。

**第二类问题——超纲语法**。AI 经常给你用一些你没学过的语法——装饰器、元类、上下文管理器、甚至设计模式。比如你只是想存两个字段，AI 给你写了个 `@dataclass`；你想简单封装一下，它给你来个抽象工厂。这些语法不是不能用，但如果你自己看不懂——要么查清楚再保留，要么简化掉。**看不懂的代码，不要上线**。

### [2:15-3:15] 问题三：边界缺失

**【画面】** 同一段代码，这次高亮 `d.get("data", [])` 这行。然后在终端模拟三种边界场景：API 返回空列表、某条记录没有 score 字段、score 为 None。

**【旁白】** **第三类问题——边界缺失**。这是最危险的一类。

还是刚才那段代码，问自己几个问题：如果 API 返回的 `data` 是空列表，会怎样？如果某条记录根本没有 `score` 字段，会怎样？如果 `score` 的值是 `None`，又会怎样？

好消息是——这段代码用了 `.get("score")`，拿到 None 后做了判断，还算靠谱。但你看原始版本：

```python
if i["score"] > 50:
```

直接用方括号取值。万一某条记录没有 `score` 字段，立刻 `KeyError` 崩掉。审查时养成一个习惯——**对每一个取值操作问一句："如果它不存在或者为 None 怎么办？"** 空列表、None 值、空字符串，这三类边界必须处理。

### [3:15-4:15] 问题四：异常处理粗暴 & 问题五：过度工程化

**【画面】** 左边展示一个 `except Exception as e: pass` 的代码片段，打一个红色大叉。右边展示一段简单需求被写成了三个类加一个工厂方法，旁边标注"杀鸡用牛刀"。

**【旁白】** **第四类问题——异常处理粗暴**。最常见的两种：一种是完全不加异常处理，网络请求、文件操作、JSON 解析全都裸奔，任何一个出错程序就崩。另一种更隐蔽——用一个 `except Exception` 把所有异常全部吞掉，出了错你都不知道。审查标准很简单：**涉及外部操作的地方——网络请求、文件读写、JSON 解析——必须有 try/except，而且要区分异常类型**，至少打一条日志告诉你到底出了什么错。

**第五类问题——过度工程化**。你跟 AI 说"写一个函数，把列表里分数大于 50 的挑出来"，正常三五行循环就搞定了。AI 可能给你写一个类，里面带工厂方法、策略模式、配置管理。杀鸡用牛刀。简单需求不需要复杂架构。审查时问自己：**三行能搞定的事，需要写一个类吗？** 如果是初学阶段，优先选简单直接的写法。

### [4:15-5:45] 审查清单速查卡

**【画面】** PPT 展示一张"AI 代码审查清单"卡片，五个条目逐条弹出，每条配一句话标准。最后整张卡片定格，适合截图保存。

**【旁白】** 五类问题讲完了，把它们浓缩成一份审查清单。以后拿到 AI 代码，过一遍这五条：

**第一，命名**——变量名、函数名是否见名知意？标准：陌生人看一眼就知道存什么。

**第二，超纲**——有没有用你没学过的语法？标准：看不懂的先查，查完决定保留还是简化。

**第三，边界**——空值、None、空列表有没有处理？标准：问一句"传入空列表会怎样"。

**第四，异常**——网络请求、文件操作有没有 try/except？标准：外部操作必须有异常处理。

**第五，过度设计**——简单需求有没有过度封装？标准：三行能搞定的事不需要一个类。

这张清单建议截图保存。每次拿到 AI 代码，花两分钟过一遍——比你凌晨两点 debug 省时间。

### [5:45-7:30] 可运行闭环：审查 bad_code.py

**【画面】** VS Code 中打开 `bad_code.py`，终端运行后展示结果。然后逐项对照清单审查，在代码上做标注。最后展示审查后的 `good_code.py` 关键改动。

**【旁白】** 来看一个完整的审查闭环。这是一段 AI 生成的代码，功能是调用 API 获取数据，筛选分数大于 50 的记录，保存到文件。先运行一下——功能正常，能跑。

现在用审查清单过一遍。

**命名**——`r`、`d`、`i`、`s` 全是单字母，改名：`response`、`data`、`item`、`score`。

**异常**——`requests.get` 完全没有异常处理。网络超时、API 返回 404，任何一个都会让程序崩溃。加上 try/except，区分超时和 HTTP 错误。

**边界**——原始代码用 `d["data"]` 取值，万一 API 没返回 data 字段就崩了。改成 `data.get("data", [])`，安全取值。

**资源管理**——文件操作 `open` 之后手动 `close`，如果中间出错文件不会关闭。改成 `with open()` 自动管理。

**安全**——API Key 硬编码在代码里，这是大忌。改成从环境变量 `os.environ.get("API_KEY")` 读取。

改完后，把筛选逻辑单独提取成 `filter_high_scores` 函数——这样后面可以单独测试它。来看审查后的版本：

```python
def fetch_items(api_url, api_key):
    try:
        response = requests.get(
            api_url,
            headers={"Authorization": f"Bearer {api_key}"},
            timeout=10
        )
        response.raise_for_status()
        data = response.json()
        return data.get("data", [])
    except requests.exceptions.Timeout:
        print("警告：请求超时")
        return []
    except requests.exceptions.RequestException as e:
        print(f"警告：请求失败 {e}")
        return []
```

异常分类型捕获，边界用 `.get()` 安全取值，超时返回空列表而不是崩溃。这就是"审查后再生"的效果——同样的功能，可靠性强了一个量级。

import requests

def processData(url, key):
    r = requests.get(url, headers={"Authorization": f"Bearer {key}"})
    d = json.loads(r.text)

    for i in d.get("data", []):

### 文件 2：good_code.py（审查重构后的代码）

```python
# good_code.py —— 审查重构后的版本
import json
import os

import requests


def fetch_items(api_url, api_key):
    """调用API获取数据列表

    参数:
        api_url: API 地址
        api_key: API 密钥
    返回:
        list: 数据列表，失败时返回空列表
    """
    try:
        response = requests.get(
            api_url,
            headers={"Authorization": f"Bearer {api_key}"},
            timeout=10
        )
        response.raise_for_status()
        data = response.json()
        return data.get("data", [])
    except requests.exceptions.Timeout:
        print("警告：请求超时")
        return []
    except requests.exceptions.HTTPError as e:
        print(f"警告：API 返回错误 {e}")
        return []
    except requests.exceptions.RequestException as e:
        print(f"警告：请求失败 {e}")
        return []


def filter_high_scores(items, threshold=50):
    """从列表中筛选分数超过阈值的记录

    参数:
        items: 记录列表，每条记录有 name 和 score 字段
        threshold: 分数阈值，默认 50
    返回:
        list: 筛选后的记录列表
    """
    result = []
    for item in items:
        score = item.get("score")
        if score is not None and score > threshold:
            result.append({"name": item["name"], "score": score})
    return result


def save_to_json(data, filename):
    """保存数据到JSON文件

    参数:
        data: 要保存的数据
        filename: 目标文件名
    """
    try:
        with open(filename, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)
    except OSError as e:
        print(f"警告：保存失败 {e}")


def main():
    api_url = os.environ.get("API_URL", "https://api.example.com/items")
    api_key = os.environ.get("API_KEY", "")

    items = fetch_items(api_url, api_key)
    filtered = filter_high_scores(items, threshold=50)
    save_to_json(filtered, "output.json")
    print(f"完成，共 {len(filtered)} 条")


if __name__ == "__main__":
    main()
```

### 重构前后对比表（幻灯片用）

| 维度 | 重构前 | 重构后 |
|---|---|---|
| 命名 | `r`, `d`, `i`, `s`, `n` | `response`, `data`, `item`, `score` |
| 异常处理 | 无 | 超时/HTTP错误/请求异常分别捕获 |
| 边界 | `d["data"]` 可能 KeyError | `data.get("data", [])` 安全取值 |
| 文件操作 | `open()` + 手动 `close()` | `with open()` 自动关闭 |
| API Key | 硬编码 `"sk-12345"` | 从环境变量 `os.environ.get()` 读取 |
