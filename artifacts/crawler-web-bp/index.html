    ③讲师自己踩的坑 · 首页被抓了两次

    讲师自己的爬虫把首页抓了两次：首页是 index.html，而页面里「1」那个链接又指向 index.html —— 字符串不同 → 判重失效 → 重复抓取。 字典的 key 唯一没错，错在 key 没先归一化：相对路径、结尾斜杠、默认页、#fragment 都会让同一个页面变成两个字符串。

    from urllib.parse import urljoin, urldefrag
    def norm(base, href):
    u = urldefrag(urljoin(base, href))[0] # 补绝对路径 + 去掉 #fragment
    path, _, qs = u.partition("?")
    path = path.rstrip("/") or "/" # 结尾斜杠去掉（根除外）
    return path + ("?" + qs if qs else "")
    seen = {norm(base, "/"): False} # key 先归一化，字典才真的能去重

    ④为什么「后端动态」不等于「必须无头」

    一个页面什么时候才需要无头浏览器，只看一件事：响应体里有没有内容。

    • 有完整 HTML → requests + 选择器就够（静态站、后端渲染的站都属这类）
    • 只有空壳 + 页面自己也在要数据 → 先按 F12 找 XHR；有可用接口就直接取 JSON
    • 接口也拿不到，或必须完整执行页面 → 再轮到 Selenium / Playwright（headless 为教学扩展）
    判断动作只有一步：Ctrl+U 看源码，或者 curl 一下看响应体。 源码里就有学生名单 → 这站对爬虫是「静态」的，哪怕它是 Flask 现场生成的。

    ⑤服务器侧怎么把请求交给 Python · 不影响你看到什么，但影响开销、整合度与灵活性Web 开发 · 第十一节 P2

    CGI 一个请求起一个进程 跑完就退出，下次再来再起。讲师原话：进程起太多「切换不过来了，它挂了」—— 就是常说的 web 服务器被 DoS
    FastCGI 常驻进程 + IPC 复用 逻辑不变，只是把「不断起新进程」这一步干掉了，请求靠进程间通信送进去
    WSGI Python 侧的调用约定 server → 中间件（多给一个 callback）→ 应用函数；小作业里 Flask 自带 HTTP 与 WSGI，不必装 Apache / Nginx 这类独立服务器

    这三种是「服务器怎么把请求交给 Python 程序」的管道差异：客户端拿到的仍是一整串 HTML，所以静态抓取照样有效；对工程而言它决定的是开销、整合度与部署灵活性 —— 能不能换掉 web server、能不能在中间件里加日志与鉴权，都在这一层。以上 CGI / FastCGI / WSGI 三段出自 Web 开发课，非爬虫课原话

    本屏结论

    后端动态 ≠ 必须无头。响应体里有完整 HTML，就能 requests + BeautifulSoup 直接抓； 真正需要浏览器的是「内容由 JS 在客户端画出来」的那种页面。

    拿到一个 URL 先做什么？

    ← 点左边任一分支，展开它的「代价 / 代码骨架 / 坑」

    代价
    最低。一次 requests.get 拿到结构化数据，不渲染、不解析 DOM；前置成本只是「找到接口」。
    骨架 
    api = "https://site.com/api/comments?page=1"
r = requests.get(api, headers=HDR, timeout=10)
items = r.json()["data"]["list"]
    坑
    接口常校验 Referer / Cookie / 签名；响应可能是 JSONP，先剥回调壳；分页参数顺着 Network 里的请求一个个翻。
    代价
    低。整页 HTML 已经就绪，写选择器即可；页面改版时选择器要跟着改，这是主要维护成本。
    骨架 
    import requests
from bs4 import BeautifulSoup

r = requests.get(url)
r.encoding = "utf-8"                       # 不指定编码，中文会乱码
soup = BeautifulSoup(r.text, "html.parser")
for li in soup.select("li"):               # li 选出来是一整个 list
    print(li.text)                         # .text 只要元素里的文本
    坑
    不写 r.encoding = "utf-8" 中文就乱码；<a href> 是相对链接，要拼上前缀才是完整 URL；select 返回 list，要逐个 .text 取文本。
    代价
    最高。启浏览器、占内存、每页数秒；部署还要装 driver 与浏览器，能不用就不用。
    骨架 
    driver.get(url)
WebDriverWait(driver, 10).until(
    EC.presence_of_element_located((By.CSS_SELECTOR, ".comment-item")))
html = driver.page_source
    坑
    用显式等待，别用 time.sleep；等 networkidle 或滚动触发懒加载；关图片、禁视频能明显提速。

    自测 · 3 题

    都是 06 那三个案例的情境 0 / 3
    01

    【案例 A】抓静态学生名单，最后对账发现首页被抓了两次。最先该改哪一处？

    答案 Bindex.html 和「1」指向同一页，但字符串不同 —— 字典按字符串比对，判重就失效了。先去锚点、去尾斜杠，再拿归一化后的结果当 key。

    02

    【案例 B】首屏只有 20 条，Network 里滚出一条 data?page=2 且返回 JSON。最优做法是？

    答案 B接口已经暴露在 Network 里、又不用鉴权，每页一次请求就拿完；headless 能拿到，但要等渲染，留作接口抓不到时的兜底。

    03

    【案例 C · 来自 Web 开发课】库存 1000→999，页面没跳、Doc 只请求了 1 次。这说明发生了什么？

    答案 B整页只请求 1 次、页面没跳，却只有那个数字变了 —— 数字来自 XHR 响应。只要这一个数，就优先打接口，别去解析 DOM。
