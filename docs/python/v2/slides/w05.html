开场演示：两个痛点

痛点一：失忆 跑 L9 的对话程序，聊了三轮 → 关掉重跑 → 历史全没了。 → 文件 IO：把数据存成 JSON，重启读回来。
痛点二：脆弱 拔掉网线再跑 → 红色 Traceback 满屏，程序当场崩溃。 → 异常处理：接住错误，优雅降级。

文件 IO：把数据存下来

import json

# 存：对话历史 → JSON 文件
with open("history.json", "w", encoding="utf-8") as f:
    json.dump(messages, f, ensure_ascii=False, indent=2)

# 读：JSON 文件 → Python 对象
with open("history.json", encoding="utf-8") as f:
    messages = json.load(f)
  • 模式："r" 读 / "w" 覆盖写 / "a" 追加
  • with 语句保证文件一定被关闭（出异常也会关）——处理文件的标准写法

异常处理：接住错误

try:
    resp = client.chat.completions.create(...)
except ConnectionError as e:
    print("网络不通，稍后重试：", e)
except FileNotFoundError:
    messages = []              # 首次运行没有历史文件，给个空列表
finally:
    print("本次调用结束")   # 无论如何都执行
  • 读报错的方法：Traceback 从最后一行往前读——最后一行是错误类型和原因
  • 捕获要具体：except Exception 一把梭会吞掉所有错误，让 bug 更难找
  • AI 场景三大常见异常：网络超时、API Key 无效、返回格式异常

类：把数据和操作装进同一个盒子

痛点回顾：client、history、api_key、model、system_prompt 五个变量在函数间传来传去——

class AIChatManager:
    def __init__(self, api_key, model="deepseek-chat"):
        self.api_key = api_key          # 属性：数据
        self.model = model
        self.history = []               # 对话历史也装在盒子里

    def send(self, text):              # 方法：操作
        self.history.append({"role": "user", "content": text})
        # ...调用 API（此处省略）...

    def clear(self):
        self.history = []

chat = AIChatManager("sk-...")     # 类是图纸，chat 是实例（产品）
chat.send("你好")
  • self 指向实例本身；__init__ 是出厂设置
  • 什么时候用类：一组数据和操作它的函数高度耦合时——你用的 OpenAI client 本身就是类的实例
