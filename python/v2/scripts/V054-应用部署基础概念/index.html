    逐字稿¶

    [0:00-0:35] 开场 hook：换个电脑就跑不起来？¶

    【画面】 终端中执行 git clone 拉取一个项目，然后 python main.py，立刻报错 ModuleNotFoundError: No module named 'fastapi'。紧接着展示另一个项目，python main.py 报错 KeyError: 'DEEPSEEK_API_KEY'。画面定格，红色大字："换个电脑就跑不起来？" 切到绿色大字："部署 = 让应用在任何地方都能跑"。

    【旁白】 看这个场景——你在自己电脑上写完了项目，一切正常。换一台电脑，git clone 下来，一跑就报错：缺依赖、找不到 API Key、路径不对。这种项目，答辩时可能翻车，更别说让别人用了。

    今天这集讲部署的基础概念。不是教你搭云服务器——而是几条工程纪律，让你的应用"换个电脑也能跑"。课程不强求所有组都部署上线，但本地完整运行演示，是底线要求。

    [0:35-2:00] 部署到底是什么¶

    【画面】 PPT 展示一张三级阶梯图。第一级："开发环境——你的电脑"（图标：笔记本电脑，标注 VSCode + 本地运行）。第二级："可移植——任何电脑 clone 下来就能跑"（图标：两个箭头指向不同的电脑）。第三级："云部署——任何人通过网址访问"（图标：云朵 + 全球用户）。三级的文字下方标注："本课程目标：至少达到第二级"。

    【旁白】 先搞清楚"部署"到底指什么。很多人一听部署就想到买云服务器、配域名、搞 HTTPS——那是云部署。但对初学者来说，部署有一个更基本的前提：你的应用能不能在另一台电脑上跑起来？我见过太多项目，开发的时候一切正常，答辩演示前换台电脑就崩了。

    我把部署分成三个层次。

    第一层，开发环境，就是你自己的电脑。你的代码在这里能跑——但只有这里能跑。依赖装在全局环境里，API Key 写死在代码里，文件路径是 C:\Users\xxx\...。这种项目，换个电脑必死。答辩的时候用教室电脑演示，一跑就报错，现场非常尴尬。

    第二层，可移植。别人 git clone 下来，按说明装好依赖、配上环境变量，就能跑起来。这是本课程对每组的基本要求，也是今天讲的重点。

    第三层，云部署。把应用放到服务器上，全世界任何人打开浏览器输入网址就能用。这层是加分项，不强求所有人做，但概念你要知道。

    今天重点讲第二层怎么做到，第三层做个概念介绍。

    [2:00-3:45] 三件事让应用可移植：依赖、配置、路径¶

    【画面】 VS Code 中展示一个项目的目录结构对比。左侧是"不可移植的项目"——api_key = "sk-xxx" 硬编码在 main.py 里，没有 requirements.txt，代码里有 open("/Users/zhangsan/data.json") 绝对路径。右侧是"可移植的项目"——有 .env 文件、有 .env.example、有 requirements.txt、代码里用 os.path.join 拼相对路径。每个差异用红色标注圈标出。

    【旁白】 让应用可移植，核心就三件事：管好依赖、管好配置、管好路径。一句话总结就是"环境可重建、密钥不硬编码、路径不写死"。

    第一件，依赖管理。你的项目用了 fastapi、openai、numpy——别人电脑上没装这些。解决办法是生成 requirements.txt。一条命令：pip freeze > requirements.txt，它会把当前环境所有包及版本号列出来。别人拿到项目后，pip install -r requirements.txt 一把装齐。

    但要注意一个坑——如果你用了虚拟环境，pip freeze 只会列出虚拟环境里的包，这是对的。如果你在全局环境跑，会列出一大堆无关的包，别人装的时候一脸懵。所以，V029 讲的虚拟环境在这里发挥作用了——项目隔离，依赖干净。

    第二件，配置管理。API Key、模型名称这些敏感信息，绝对不能写死在代码里。两个原因：一是安全——你把 Key 推到 Git 上，别人就能盗用你的额度，这在真实工作中是严重事故；二是可移植——别人的 Key 和你的不一样，你写死了，别人就得改代码才能跑，这不合理。

    正确做法：用 .env 文件存配置，代码里用 python-dotenv 读取。仓库里放一个 .env.example，写清楚需要哪些变量、每个变量什么含义，但不含真实值。别人 clone 下来，复制一份改成自己的就行。记住，.env 文件一定要加到 .gitignore 里，不能推到 Git。

    第三件，文件路径。你代码里写 open("/Users/zhangsan/project/data.json")——换台电脑，这个路径根本不存在。正确做法是用相对路径，配合 os.path 或 pathlib。后面实操演示会展示具体写法。

    [3:45-5:15] 实操演示：可移植项目清单¶

    【画面】 VS Code 中展示一个名为 chat_app 的项目，逐个文件高亮展示。先展示 .env.example 内容，再展示 requirements.txt，再展示 main.py 中使用 load_dotenv() 和 os.path.join 的代码片段。最后终端中执行三步操作：python -m venv venv → pip install -r requirements.txt → 复制 .env.example 为 .env 并填入 Key → python main.py，显示"服务启动成功"。

    【旁白】 来看一个实际的可移植项目长什么样。这个 chat_app 是一个 FastAPI 的 AI 聊天后端。

    先看 .env.example——它列出了所有需要配置的环境变量，每个变量都有注释说明：

    # DeepSeek API（必填）
DEEPSEEK_API_KEY=your_api_key_here
# 模型名称（可选，默认 deepseek-chat）
MODEL_NAME=deepseek-chat

    再看 requirements.txt——每个依赖精确到版本号，别人装出来和你一模一样。

    然后看 main.py。开头两行：

    from dotenv import load_dotenv
load_dotenv()

    这两行把 .env 文件里的变量加载到环境变量。代码里用 os.environ.get("DEEPSEEK_API_KEY") 读取——不写死，运行时从环境拿。

    文件路径用 os.path.join：

    data_path = os.path.join(os.path.dirname(__file__), "data", "faq.json")

    这样不管项目放在哪，路径都对。

    别人拿到这个项目，三步就能跑：建虚拟环境、装依赖、填 .env、启动。不到两分钟。

    [5:15-6:10] 云部署概念：从本地到全世界¶

    【画面】 PPT 展示一张架构图。左侧"你的电脑运行 uvicorn"——只能 localhost 访问。中间"PaaS 平台（如 Railway / Render）"——你推代码，平台自动构建、自动分配域名。右侧"全球用户通过 https://yourapp.com 访问"。下方标注两类方案："PaaS：简单，适合初学者"和"VPS：灵活，需要 Linux 基础"。

    【旁白】 本地能跑了，如果想让全世界都能访问呢？这就需要云部署。

    初学者推荐了解 PaaS 平台，比如 Railway、Render 这类。原理很简单：你把代码推上去，平台自动帮你装依赖、启动服务、给你一个网址。你不需要管服务器，只需要保证项目本身是可移植的——就是前面讲的三件事。PaaS 一般有免费额度，学生项目完全够用。

    另一类是 VPS，比如阿里云、腾讯云的云服务器。你自己装 Python、配环境、跑服务。灵活但门槛高，需要 Linux 命令行基础，还要处理防火墙、域名解析这些问题。

    课程不强求做云部署。但如果你的项目前三件事做得好，部署到 PaaS 只需要加一个配置文件，十分钟就能上线。感兴趣的同学可以课后尝试，做出来是简历上的亮点。

    [6:10-6:45] 部署检查清单¶

    【画面】 终端中展示一个 checklist，逐条打勾。标题："部署前自查清单"。六条依次亮起绿色勾号：1. requirements.txt 存在且完整 2. .env 不在 Git 中（.gitignore 已配） 3. .env.example 存在且说明清晰 4. 代码无硬编码 Key 5. 无绝对路径 6. README 有启动步骤。

    【旁白】 最后给你一个部署自查清单，项目交付前逐条过一遍。

    一，requirements.txt 存在且完整。二，.env 文件确认在 .gitignore 里——千万别把 Key 推上去。三，.env.example 存在，变量说明清晰。四，全局搜一遍代码，确认没有硬编码的 Key。五，没有绝对路径。六，README 里写了启动步骤——别人照着做能跑起来。

    六条全打勾，你的项目就是可移植的。

    [6:45-7:00] 小结¶

    【画面】 字幕条："部署 = 可移植 + 可访问 · 依赖·配置·路径三件套 · 云部署是加分不是必须 · 本地能跑是底线"。

    【旁白】 记住核心：部署不是黑魔法，是工程纪律。管好依赖、配置、路径，你的应用就能在任何地方运行。本地能跑是底线，云部署是加分。

    # main.py —— 可移植的 FastAPI AI 聊天后端
"""演示可移植项目结构：依赖管理 + 环境变量 + 相对路径"""
import os
import json
from dotenv import load_dotenv
from fastapi import FastAPI
from pydantic import BaseModel
from openai import OpenAI

load_dotenv()  # 从 .env 加载环境变量

client = OpenAI(
    api_key=os.environ.get("DEEPSEEK_API_KEY", ""),
    base_url="https://api.deepseek.com"
)

app = FastAPI()

# 用相对路径读取数据文件，不依赖绝对路径
DATA_DIR = os.path.join(os.path.dirname(__file__), "data")
FAQ_PATH = os.path.join(DATA_DIR, "faq.json")


class ChatRequest(BaseModel):
    message: str


@app.get("/")
def health():
    return {"status": "ok", "model": os.environ.get("MODEL_NAME", "deepseek-chat")}


@app.post("/chat")
def chat(req: ChatRequest):
    model = os.environ.get("MODEL_NAME", "deepseek-chat")
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": req.message}]
    )
    return {"reply": response.choices[0].message.content}


@app.get("/faq")
def get_faq():
    """演示用相对路径读取数据文件"""
    if os.path.exists(FAQ_PATH):
        with open(FAQ_PATH, "r", encoding="utf-8") as f:
            return json.load(f)
    return {"error": "FAQ 数据文件不存在"}


if __name__ == "__main__":
    import uvicorn
    port = int(os.environ.get("PORT", 8000))
    print(f"服务启动: http://localhost:{port}")
    uvicorn.run(app, host="0.0.0.0", port=port)

    3. 三件套讲解对照展示：讲依赖、配置、路径三件事时，左右分屏对比"不可移植项目"和"可移植项目"的代码差异，每处差异用高亮圈标出。不要只讲概念不给代码对照。
    4. 语速控制：整体旁白约 1550 字，按 230 字/分钟控制在 7 分钟以内。实操演示段落适当放慢，云部署概念段落可以正常语速快速带过。
