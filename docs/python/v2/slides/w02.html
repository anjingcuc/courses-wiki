命令行：程序员的日常工作台

写代码
VSCode
→

hello.py
→
命令行运行

两种运行方式：
  • 交互模式 >>>：输入一句执行一句，适合做小实验
  • 文件运行：cd 到文件所在目录 → python 文件名.py

理解原理：交互演示 · 编译 vs 解释（为什么 Python 保存即可运行）

读懂命令行的「话」

# 逐行读报错：最后一行是重点
C:\Users\me> python hello.py
python: can't open file 'hello.py': [Errno 2] No such file or directory

# 翻译：当前目录下没有 hello.py → 先 cd 到正确目录
C:\Users\me> cd Desktop\py
C:\Users\me\Desktop\py> python hello.py
Hello, world!
  • 三个最常见报错：文件找不到（目录不对）、命令未找到（PATH 问题）、缩进错误
  • 排错第一步：先看自己在哪个目录（cd / dir）

API Key＝身份证 + 钱包。绝不分享、绝不提交到仓库。
Token＝计费单位。1 个汉字 ≈ 1–2 token；输入输出都计数。

第一次调用：代码骨架逐行讲

from openai import OpenAI

client = OpenAI(
    api_key="sk-你的密钥",                  # 用环境变量更安全！
    base_url="https://api.deepseek.com/v1", # 换服务商只改这里
)
resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[
        {"role": "system", "content": "你是一个耐心的编程助教"},  # 人设
        {"role": "user",   "content": "用一句话解释什么是变量"},      # 提问
    ],
)
print(resp.choices[0].message.content)      # 取出回复文本
  • 三种消息角色：system 设定人设与边界，user 是你的问题，assistant 是 AI 的回复
  • 改一改 system，AI 的风格立刻不同——这就是「Prompt 即编程」

Git：你的「后悔药」

用「拍照」类比记住三板斧：

git add
选好入镜的东西
→
git commit
按下快门
→
git push
上传云端相册
为什么「AI 大改前先 commit」？ AI 重构可能大面积改写代码。先 commit 建立还原点，效果不对一条 git checkout 就能回退——否则只能像上节课开场那样手忙脚乱地撤销。
  • 分支 = 平行宇宙：作业分支 0xNN 里随便折腾，主线不受影响
  • .gitignore 排除 .env——API Key 绝不进仓库（Git 历史删不掉，预防比补救重要一百倍）
