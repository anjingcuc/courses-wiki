## Problem Statement

现有的「Web 演进 × 爬虫技术」交互蓝图已经完整覆盖两节课程内容，但它是面向课堂投影的七场景放映器，尚未进入 courses-wiki 的 Python V2 学习路径。学生从 W06「HTTP 与数据获取」、M3「数据获取与处理」或拓展自学长廊无法发现这份内容；直接打开原型又会遇到场景切换、内部滚动、全局快捷键和横屏假设，不符合站内拓展阅读的使用方式。

需要把它整合为一篇可从 W06 进入的独立交互阅读页，在保留教学内容和图内交互的同时，使阅读节奏、视觉语言、移动端体验和无障碍行为与网站整体一致。

## Solution

新增一种独立于周课件末尾「拓展自学」的**拓展阅读**形态：以连续长页承载七个教学主题，从 W06 课后阅读、M3 延伸阅读和拓展自学长廊进入同一页面。

阅读页采用正常文档流和语义章节锚点，不再使用场景放映、自动翻页或内部滚动容器。外层使用 Python V2 的浅色纸面、卡片、标题层级、圆角与 sky/violet 强调色；工程蓝图作为图内视觉语言保留。所有架构图、流程图、CSS/XPath 工作台、案例练习与自测继续可操作，且滚动浏览不会清空用户状态。

原课堂版保留，拓展阅读版从同一份场景内容源构建，避免两套教学内容逐渐漂移。

## User Stories

1. 作为学习 W06 的学生，我想在课后阅读区看到这篇拓展阅读，以便把课堂上的 HTTP 与数据获取知识串成完整图景。
2. 作为浏览 M3 的学生，我想从延伸阅读进入同一页面，以便按模块主题继续学习，而不必先找到具体周课件。
3. 作为浏览拓展自学长廊的学生，我想在 M3 分组中看到这篇阅读，以便发现与数据获取相关的交互内容。
4. 作为学生，我想从任一入口到达同一篇阅读，以便收藏、分享和返回时都得到一致内容。
5. 作为学生，我想通过连续向下滚动阅读七个主题，以便像阅读文章一样学习，而不是操作课堂放映器。
6. 作为学生，我想通过页内目录跳到指定主题，以便快速复习「一次往返」「完整 HTML」「动态两条路」或「CSS/XPath」。
7. 作为学生，我想使用语义化章节链接，以便把某个具体主题分享给同学。
8. 作为学生，我想从阅读页返回 W06，以便继续本周课程主线。
9. 作为学生，我想从阅读页返回 M3 或拓展自学长廊，以便不丢失原来的学习入口。
10. 作为学生，我想先看到 Web 供给形态与爬虫对策的总图，再逐层进入机制、工具与案例，以便建立从总到专的认知结构。
11. 作为学生，我想点击总图中的供给形态节点，以便同步观察 HTML 生成位置、响应内容和推荐抓取路线。
12. 作为学生，我想点击 HTTP 往返图中的节点与资源，以便查看对应报文、字段和子资源请求。
13. 作为学生，我想在完整 HTML 场景中切换模板参数，以便看到相同模板如何生成不同响应。
14. 作为学生，我想在动态页面场景中沿图选择执行 JS 或直接取 JSON，以便理解两条路线的适用条件与代价。
15. 作为学生，我想在同一棵 DOM 树上输入 CSS 或 XPath，以便看到页面、源码和树节点对同一目标的同步高亮。
16. 作为学生，我想点击 DOM 节点同时获得 CSS 与 XPath 写法，以便把表达式和真实元素建立对应关系。
17. 作为学生，我想完成 URL 判重、分页 JSON 与库存局部更新案例，以便把路线选择用于具体问题。
18. 作为学生，我想在选错案例路线时看到代价说明并继续重试，以便理解错误原因而不是只得到对错。
19. 作为学生，我想完成末尾决策树与三题自测，以便检查自己是否能独立选择抓取策略。
20. 作为学生，我希望滚动离开再返回章节时保留练习、自测和表达式状态，以便连续阅读不会破坏已有进度。
21. 作为手机用户，我想让多列工作台在窄屏拆列，以便无需缩放页面即可阅读文字和操作控件。
22. 作为手机用户，我想在明确标识的横向容器中查看超宽工程图，以便图中文字不被整体缩到不可读。
23. 作为触摸设备用户，我想让主要交互目标具有足够大的点击区域，以便准确选择节点、选项和表达式模式。
24. 作为使用减少动态效果设置的用户，我想关闭非必要入场与循环动画，以便减少干扰和不适。
25. 作为键盘用户，我想正常使用浏览器查找、刷新、新建标签与页面滚动快捷键，以便不被阅读页的全局快捷键劫持。
26. 作为屏幕阅读器用户，我想让页面具有清晰的标题、章节、按钮状态和导航语义，以便理解结构与当前交互状态。
27. 作为教师，我想保留课堂投影版，以便继续在教室中使用已有七场景蓝图。
28. 作为教师，我想让阅读版与课堂版复用同一份教学内容源，以便修正课程表述时只维护一次。
29. 作为教师，我想明确区分课程原例、教学重绘、演示数据与扩展知识，以便学生不会把补充内容误认为讲师原话或实测结果。
30. 作为内容维护者，我想在不改变 W06、M3 与第 11/12 章既有映射的前提下增加阅读入口，以便不引入课程主线漂移。
31. 作为站点维护者，我想让阅读页不依赖 CDN、远程字体或运行时接口，以便保持离线可用和部署简单。
32. 作为站点维护者，我想用现有站点构建与链接检查发现集成问题，以便新增页面符合既有发布流程。
33. 作为视觉维护者，我想让外层遵循 Python V2 设计系统，以便页面看起来属于 courses-wiki，而不是独立产品。
34. 作为视觉维护者，我想让蓝图线稿只出现在教学图内，以便保留作品特色而不破坏网站整体语言。
35. 作为后续开发者，我想通过真实构建后站点的浏览器测试验证功能，以便测试用户行为而非内部实现细节。

## Implementation Decisions

1. **页面形态**：新增独立 HTML 拓展阅读页，不使用 iframe 包装，也不把整份应用直接塞入 Material 正文。
2. **领域语言**：拓展阅读指从课程主线进入的独立交互长页；周课件末尾的 slides.js 内容仍称拓展自学。将该术语加入项目词汇表，避免与拓展自学、拓展长廊混用。
3. **内容复用**：七个主题的 HTML、样式与交互源码继续作为唯一教学内容源；阅读版和课堂版由不同外壳生成。
4. **构建边界**：扩展现有组装器，同时生成课堂版与阅读版；发布文件属于构建产物，不手工维护第二份副本。
5. **阅读结构**：七个主题全部在正常文档流中展示，以语义化锚点导航；不再存在唯一活动场景或场景内部滚动。
6. **导航行为**：提供返回 W06 的明确入口以及与 M3、拓展长廊的返回路径；页内目录只负责章节定位，不承担翻页。
7. **移除放映器行为**：阅读版不提供自动放映、全屏、场景翻页、深色蓝图切换、场景遮罩目录或全局场景快捷键。
8. **初始化契约**：每个主题只初始化一次；滚动进入视口不得重播整段或重置练习、自测、表达式状态。重播只允许由用户针对局部动画显式触发。
9. **滚动兼容**：场景内依赖根容器滚动的定位、回到顶部和可见性观察逻辑必须支持阅读模式的窗口滚动与视口观察。
10. **锚点兼容**：总结场景中的场景编号深链改为真实章节锚点，不再改写为放映器的数字路由。
11. **仿真链接**：选择器示例中的导航、封面等伪链接不得离开阅读页；它们是 DOM 教学样本，不是站点导航。
12. **视觉分层**：页面外层使用 Python V2 的浅色纸面、slate 文字、sky/violet 强调、14–16px 容器圆角与轻量层级；图内继续采用细线、节点、连线与尺寸标注等蓝图语言。
13. **主题策略**：阅读版只提供浅色主题，不与 Material 或课堂版建立独立主题存储；课堂版原有深浅主题保持不变。
14. **动效策略**：保留解释请求、渲染、节点命中和状态变化所必需的教学动画；非必要动画服从系统减少动态效果设置，包括 CSS 无限动画。
15. **响应式策略**：桌面保持完整图解；平板和手机将工作台与多列内容拆列。无法有意义缩放的超宽图放入有提示的横向查看容器，不允许整页横向溢出。
16. **触摸与输入**：主要操作具有足够触摸面积；输入框、案例选项、自测与目录在窄屏仍可操作；避免嵌套滚动和仅依赖 hover 的信息入口。
17. **可访问性**：保留语义标题与章节结构，为展开、选中和命中状态提供可感知状态；保证清晰焦点样式与文本对比度。
18. **入口集成**：W06 课后阅读、M3 延伸阅读和拓展自学长廊使用原生 HTML 的最终发布 URL 指向同一阅读页；不新增顶层导航。
19. **课程映射**：不修改周映射事实源，不修改任何 WEEKMAP 标记区，只新增普通资源链接并检查映射无漂移。
20. **内容边界**：完整保留七主题、案例练习和自测；保持课程原例、教学重绘、示意数据与 XPath、headless、Playwright 等教学扩展的出处标注。
21. **资源策略**：阅读版继续使用本地内联或站点已有资源，不增加 CDN、Webfont、远程图片、分析脚本或运行时数据请求。
22. **旧版保护**：不重写旧场景归档，不修改第三方 vendored 库，不直接编辑 MkDocs 输出目录。
23. **架构决策记录**：本次新增入口与阅读外壳可逆且沿用现有独立演示模式，不新增 ADR；仅补充必要领域术语。

## Testing Decisions

1. **最高层主接缝**：从 MkDocs 构建后的站点运行 Playwright，测试真实发布页面与入口，而不是只测试独立源码或内部函数。
2. **入口行为**：分别从 W06、M3 和拓展自学长廊点击进入阅读页，验证目标正确、无断链，并可返回相应学习上下文。
3. **连续阅读行为**：验证七主题同时存在于文档流、章节锚点可用、滚轮与 Space/PageDown 只滚动页面，不发生场景切换。
4. **浏览器行为**：验证阅读页不抢占 Ctrl/Cmd 组合键、浏览器查找/刷新/新建标签等习惯操作，不注册翻场触摸手势。
5. **核心图内交互**：覆盖总图节点读数、HTTP 节点报文、模板参数切换、动态分岔定位、CSS/XPath 等价命中、DOM 节点双语法生成、案例反馈和自测计分。
6. **状态保持**：完成表达式输入、案例选择或自测后滚动离开再返回，验证状态不被初始化或入场动画重置。
7. **响应式外部行为**：至少覆盖桌面横屏、平板宽度和约 390px 手机视口；验证无整页横向溢出、文字可读、主要控件可触摸、超宽图仅在自身容器内横向滚动。
8. **减少动态效果**：以系统减少动态效果偏好加载页面，验证内容和交互仍完整，非必要循环动画停止。
9. **运行健康**：监控控制台错误、页面异常和意外网络请求；仿真 B 站链接不得导航出当前阅读页。
10. **视觉检查**：对关键章节和交互状态截图，检查 V2 外层一致性、蓝图图内可读性、遮挡、重叠、孤立文字与折线切割。
11. **课堂版回归**：运行现有七场景审计，确认新增阅读外壳和共享场景调整未破坏课堂版导航、双主题和图内交互。
12. **站点构建接缝**：运行周映射只读检查、完整 MkDocs 构建与全站断链检查；周映射必须无漂移，新增链接必须有效。
13. **测试原则**：断言用户可见行为、URL、布局与状态，不绑定时间线实例、私有函数、DOM 类名等可自由重构的实现细节。
14. **既有先例**：沿用当前蓝图项目的 Playwright 截图与交互回归方式，但阅读版测试目标改为构建后站点，而非课堂版深链。
15. **已知噪声**：断链检查中的 reveal notes-server 两条已知误报单独记录，不用放宽其他链接规则来掩盖它们。

## Out of Scope

- 不重新撰写或扩展七主题的课程知识体系，不新增新的爬虫技术章节。
- 不把内容拆入 W06 末尾的 slides.js 拓展自学，也不制作阅读/放映双模式切换。
- 不将阅读页嵌入 iframe，不把它重构为 Material 正文组件。
- 不新增站点顶层导航，不改变 W06 与 M3、第 11/12 章的既有映射。
- 不提供阅读版深色主题、用户账户、云端进度保存、评论或学习分析。
- 不对真实第三方站点执行抓取，不新增绕过认证、验证码、访问控制或反爬机制的内容。
- 不替换现有技术栈，不引入新的前端框架或第三方运行时依赖。
- 不修改旧版场景归档、第三方 vendored 库或 MkDocs 构建输出。
- 不在本规格实施中提交、推送或部署；发布仍走既有流程。

## Further Notes

- W06「HTTP 与数据获取」属于 M3，主对照为第 11 章「Web 分析与爬虫」，次对照为第 12 章「爬虫」。拓展阅读是资源增强，不改变这条课程主线。
- 现有原型已经过七场景、双主题与横屏交互审计；本次主要风险不在教学内容，而在从场景放映器转为正常文档流后的滚动、状态保持和窄屏行为。
- 教学图允许保留蓝图特色，但页面外壳必须让位于 Python V2 的整体设计语言。
- 本地预览与线上验证都必须保留 GitHub Pages 的课程站点子路径，原生 HTML 链接不能使用会丢失该前缀的根相对地址。
