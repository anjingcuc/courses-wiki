# 3.2 运行方式——环境变量

## 内容梗概

本课讲解环境变量的概念及其对运行 Python 的影响。老师先现场模拟了一个典型错误：安装 Python 时没有勾选"把 Python 加入环境变量"，导致在 cmd 中输入 `python` 没有反应，Windows 10 甚至会弹出 Microsoft Store 让你"安装 Python"。接着通过画图讲解 Windows 查找可执行程序的机制：输入命令回车后，系统会按顺序查找用户（user）环境变量和系统（system）环境变量中名为 `Path` 的变量，在其保存的目录列表里逐个寻找 `python.exe`。最后演示了补救方法：手动把 Python 安装目录添加进 `Path`，并强调修改后要重启 cmd 才能生效。

## 知识点详解

### 未添加环境变量时的典型错误

- 场景：安装 Python 时没有勾选"将 Python 3.8 加入环境变量"（约 00:11）。
- 现象一：在 cmd 中输入 `python` 回车后没有任何反应（约 00:42）。
- 现象二：Windows 10 下会弹出 Microsoft Store（微软应用商店）窗口，提示你去安装 Python——系统在机器上没找到 Python，以为你要装（约 00:55）。
- 如果输入的是一个应用商店里也搜不到的程序，系统会报错："不是内部或外部命令，也不是可运行的程序或批处理文件"（约 09:37）。

### 环境变量的工作机制

- 你在 cmd 中输入 `python` 回车后，Windows 会自动去查环境变量（约 01:59）。
- 环境变量分两类（约 03:05）：
  - 用户（user）环境变量：只对当前用户生效，其他用户读不到。
  - 系统（system）环境变量：所有用户都能读取，影响所有用户。
- 系统会按顺序在这两类环境变量中查找一个名为 `Path` 的变量（约 03:46）。
- `Path` 变量里存的是一个目录列表（目录一、目录二、目录三……），系统会按顺序逐个目录寻找 `python.exe`，直到找到为止（约 07:39）。
- 你只输入 `python` 而没有输入 `.exe`，系统会自动补全扩展名查找：找 `.exe`、`.bat`（批处理文件）等可执行类型，优先找 `.exe`（约 08:07）。

### 查看和修改环境变量的路径

- 操作路径：此电脑右键 → 属性 → 高级系统设置 → 环境变量（约 03:18）。
- 窗口中上半部分是用户环境变量，下半部分是系统环境变量。

### 补救：手动添加 Path

- 在环境变量窗口中选中 `Path`，把 Python 的安装目录（示例中为 D 盘下的 Python 目录）添加进去，务必点"确定"（点"取消"就白设置了）（约 10:31）。
- 修改后必须**关闭并重新打开 cmd** 才能生效——已打开的 cmd 仍加载旧的环境变量（约 11:51）。
- 老师演示中遇到"车祸现场"：改用户环境变量后重启 cmd 仍未生效（用户级变量可能需要注销重登），改系统环境变量后才成功（约 12:25）。若在系统级 `Path` 中修改，重开 cmd 即可生效。

### 本质理解

- 通过环境变量 `Path` 找到 `python.exe` 并运行它，效果等同于直接双击 `python.exe`（约 13:38）。

## 示例与演示

- 现场删掉所有 Python 相关的环境变量，模拟"输入 python 没反应 / 弹出应用商店"的错误场景。
- 画图演示 cmd 输入命令 → 查找 user/system 环境变量 → 定位 `Path` → 遍历目录列表 → 找到 `python.exe` 的完整链路。
- 演示补救操作：在 D 盘 Python 安装目录确认后，把该目录加入 `Path`（用户级尝试失败，改系统级成功），重开 cmd 后 `python` 命令正常进入交互模式。

## 重点与难点

- 为什么安装时要勾选"添加环境变量"：不添加的话，cmd 中输入 `python` 系统找不到 `python.exe`。
- `Path` 中目录是按顺序查找的；找不到就报"不是内部或外部命令"或弹出应用商店。
- 修改环境变量后必须重启 cmd 才能生效；用户级变量的修改可能需要注销才会重新加载。
- 确定、确定、一定要点确定，点取消等于没改。
- 用户环境变量 vs 系统环境变量的生效范围区别（当前用户 vs 所有用户）。
