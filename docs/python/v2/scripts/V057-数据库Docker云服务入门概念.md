### [0:35-2:30] 数据库：从字典到持久化

**【画面】** PPT 分屏对比。左侧："L29 SessionManager"——`self.history = {}` 字典存在内存，标注"⚠ 重启即丢失"。右侧："SQLite 数据库"——一个 `.db` 文件存在磁盘，标注"✅ 持久化"。中间箭头标注"5 行代码迁移"。

**【旁白】** 先讲数据库。你们做期末项目的时候，对话历史存在哪？大概率是一个 Python 字典——存在内存里。这没毛病，功能能跑。但问题来了：程序一关，内存清空，所有对话记录全没了。

数据库解决的就是这个问题——把数据存到磁盘上，关机重启都不丢。

**【画面】** PPT 展示三种数据库的选型表格。SQLite 行标注"单文件、零安装、Python 内置"，PostgreSQL 行标注"生产级、高并发"，MongoDB 行标注"非结构化、灵活"。

**【旁白】** 数据库有很多种，但你入门只需要记住三个名字。SQLite——一个文件就是一个数据库，Python 自带，不需要装任何东西，课程项目用它完全够了。PostgreSQL——生产级别，大公司用的，能扛高并发。MongoDB——存非结构化数据，字段经常变的时候用它。

你现在不需要纠结选哪个。课堂项目选 SQLite，因为零安装零配置。

**【画面】** VS Code 展示 SQLite 最小代码：connect → 建表 → 插入 → 查询。代码用不同颜色高亮四步。终端运行后输出对话历史。

**【旁白】** 来看最小代码。第一行 `sqlite3.connect("chat.db")`——如果这个文件不存在，自动创建。这就是零配置，连 `pip install` 都不需要。然后 `CREATE TABLE` 建一张表，定义好字段——session_id 标识哪个对话，role 区分用户和 AI，content 存内容。接着 `INSERT` 插数据，`SELECT` 查数据。注意这个问号占位符——传参数用问号，不要用 f-string 拼，防止 SQL 注入。

**【画面】** PPT 展示 SQLite vs JSON 文件对比。SQLite 列：条件查询、多进程并发、索引加速。JSON 列：全量读取、单进程、无索引。

**【旁白】** 有些同学可能想：我用 JSON 文件存不也行吗？行，数据量小的时候没问题。但想想这个场景——你想查"昨天某个用户说了什么"，JSON 文件你得把整个文件读进来、遍历、筛选。数据库呢？一条 SQL 搞定。而且多个进程可以同时读写数据库，JSON 文件不行。

就这么几行代码，你的对话历史就从内存字典搬到了磁盘文件里。核心变化就一个——存储位置变了，别的逻辑不用动。

### [2:30-4:30] Docker："在我电脑上能跑"

**【画面】** PPT 情景图。左侧："你的电脑" Python 3.12 + FastAPI 0.115。右侧："同学的电脑" Python 3.9 + 没装 FastAPI。中间大红叉"❌ 跑不起来"。

**【旁白】** 第二个技术：Docker。场景你一定遇到过——你把期末项目发给同学，他说"跑不起来"。缺依赖、版本不对、操作系统不同。你花了一下午帮他装环境，还是报错。这就是"在我电脑上能跑"的经典困境。

**【画面】** PPT 动画。Docker 流程图：你的电脑 → `docker build` → 一个镜像（包含 Python 3.12 + FastAPI + 你的代码）→ `docker run` → 同事的电脑。打绿色对勾"✅ 完全一致"。

**【旁白】** Docker 的思路很简单：把你的代码、Python 环境、所有依赖，打包成一个整体——叫"镜像"。别人拿到这个镜像，直接运行，环境和你一模一样。注意，这不是虚拟机——Docker 容器更轻量，启动只要几秒，资源占用很小。

打个比方。以前海运，货物形状大小各不相同，装船效率很低。后来发明了标准集装箱——所有货物先装进集装箱，船只管运集装箱。Docker 就是软件界的集装箱。你不用关心对方电脑装了什么，镜像里全都有。

**【画面】** VS Code 展示一个 Dockerfile，逐行高亮：`FROM python:3.11-slim` → `WORKDIR /app` → `COPY requirements.txt` → `RUN pip install` → `COPY . .` → `CMD`。

**【旁白】** Docker 的配置文件叫 Dockerfile，写的就是"安装步骤说明书"。看这几行：`FROM` 指定基础镜像——用官方 Python 镜像；`COPY requirements.txt` 先复制依赖文件；`RUN pip install` 装依赖；`COPY . .` 再复制你的代码；最后 `CMD` 写启动命令。

有个细节值得注意：为什么要先复制 `requirements.txt` 再复制代码？因为 Docker 有层缓存机制。你改了代码，只有最后那步 `COPY . .` 会重新执行，前面的 `pip install` 直接用缓存。如果合并在一起，每次改代码都要重新装依赖，慢十倍。AI 一般会帮你处理好，但你要能看懂为什么这么写。

### [4:30-6:15] 云计算与 Serverless

**【画面】** PPT 三层类比图。第一层"IaaS 租毛坯房"——你拿到一台服务器，自己装系统装环境。第二层"PaaS 租精装房"——环境配好了，你直接部署代码。第三层"Serverless 住酒店"——什么都不管，按使用付费。

**【旁白】** 第三个技术：云计算。你的应用写好了，在自己电脑上能跑，但怎么让别人也能访问？总不能让人家远程连你的电脑吧。你需要一台 24 小时在线的服务器——这就是"上云"。

云服务有三个层级，用一个类比帮你记住。IaaS，就像租毛坯房——云厂商给你一台服务器，系统、环境、依赖你自己装。灵活，但费事。PaaS，像租精装房——环境都配好了，你把代码丢上去就能跑。Serverless，像住酒店——你什么都不管，只写一个函数，有人调用时云平台自动运行，按调用次数付费。没人调用，一分钱不花。

**【画面】** PPT 对比表。"云主机 vs Serverless"。云主机：24 小时在线、适合有数据库和长连接的应用、固定月费。Serverless：按调用付费、适合简单 API、有免费额度、不适合长连接。

**【旁白】** 怎么选？如果你的 AI 应用有数据库、有 WebSocket 长连接——选云主机，它持续运行更合适。如果你只是做了个简单的翻译 API，每天被调用几十次——Serverless 可能一分钱都不花，因为它有免费额度。技术选型永远看场景，没有标准答案。

补充一点，现在很多云平台直接提供 AI 应用托管服务，比如你把 FastAPI 项目丢上去，它帮你处理部署、扩容、监控。对初学者来说，这比自己折腾服务器友好得多。如果你期末项目想真正上线，可以先从这种托管平台试手。

### [6:15-7:15] 选型思维：按需取用，不是全学一遍

**【画面】** PPT 展示一个决策流程图。问题 1："数据需要持久化吗？" → 是 → 用 SQLite。问题 2："部署给别人用吗？" → 是 → "环境复杂吗？" → 是 → 用 Docker / 否 → 直接部署。问题 3："需要 24 小时在线吗？" → 是 → 云主机 / 否 → Serverless。

**【旁白】** 今天一口气讲了三个技术，信息量不小。但核心心态是一句话——这些不是让你今天就精通的，而是让你知道"有这条路"。数据库解决"存"的问题，Docker 解决"跑"的问题，云解决"让别人用"的问题。

**【画面】** 决策速查表浮现。三行：数据持久化→SQLite，环境复杂→Docker，24小时在线→云主机/Serveless。

**【旁白】** 什么时候用哪个？看你的项目需求。数据需要持久化——上 SQLite。部署环境太复杂——上 Docker。要让别人也能访问——上云。每个技术本身都能学一个学期，但作为 AI 应用开发者，你需要的是知道"什么时候该用、怎么入门"。具体的实现细节，交给 AI 和文档。

你最大的优势是——你已经理解了 AI 应用的数据流，你知道对话记录长什么样、部署需要什么。这些业务理解，比 SQL 语法重要得多。给 AI 描述清楚你的需求，它能帮你写出建表语句、Dockerfile、部署脚本——但你要能看懂、能审查。

### 展示物 1：SQLite 持久化演示代码

```python
# db_demo.py —— SQLite 最小演示：对话历史的持久化
import sqlite3

# 1. 连接数据库（文件不存在自动创建）
conn = sqlite3.connect("chat.db")

# 2. 建表
conn.execute("""
    CREATE TABLE IF NOT EXISTS messages (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        session_id TEXT,
        role TEXT,
        content TEXT,
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
    )
""")

# 3. 插入对话记录
conn.execute(
    "INSERT INTO messages (session_id, role, content) VALUES (?, ?, ?)",
    ("demo001", "user", "Python 是什么？")
)
conn.execute(
    "INSERT INTO messages (session_id, role, content) VALUES (?, ?, ?)",
    ("demo001", "assistant", "Python 是一种简洁易学的编程语言。")
)
conn.commit()

# 4. 查询
rows = conn.execute(
    "SELECT role, content FROM messages WHERE session_id = ? ORDER BY id",
    ("demo001",)
).fetchall()

print("=== 会话 demo001 的历史 ===")
for role, content in rows:
    print(f"[{role}] {content}")

conn.close()
print("\n✅ 数据已存入 chat.db，关掉程序也不会丢失。")
```

**运行命令**：

```bash
python db_demo.py
```

**预期输出**：

```
=== 会话 demo001 的历史 ===
[user] Python 是什么？
[assistant] Python 是一种简洁易学的编程语言。

✅ 数据已存入 chat.db，关掉程序也不会丢失。
```

### 展示物 2：Docker 概念图（PPT 板书）

```
传统部署：
  你的电脑 (Python 3.12 + fastapi 0.115 + 你的代码)
  → 同事的电脑 (Python 3.9 + 没装 fastapi)
  → ❌ 版本不匹配，跑不起来

Docker 部署：
  你的电脑 → docker build → 镜像 (Python 3.12 + fastapi + 代码)
  → 同事的电脑 → docker run → ✅ 完全一致的环境

类比：
  镜像 (Image)  = 蛋糕配方（精确到每一克）
  容器 (Container) = 按配方做出的蛋糕
  仓库 (Registry) = 蛋糕配方商店（Docker Hub）
```

**最小 Dockerfile 示例**（讲解用，不强求实操）：

```dockerfile
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/

COPY . .

EXPOSE 8000

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```
